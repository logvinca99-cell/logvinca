# 셀업 자동 수집기 v2 — 설계도

> 목표: **스토어 주소만 붙여넣고 ▶ 시작을 누르면, 아침에 "수집 완료 / 누락 N개(삭제된 상품)" 보고서가 떠 있는 상태.**
> 지금 사람이 하는 일(URL 수집 → 파일 옮기기 → AHK 실행 → 엑셀 대조 → 재실행 2~3회)을 전부 프로그램이 한다.

---

## 1. 지금 사람이 하는 일 → v2에서 누가 하나

| # | 지금 (v1: 콘솔 JS + AHK) | v2 |
|---|---|---|
| 1 | 크롬 열고 스토어 들어가서 F12 → JS 붙여넣기 | GUI에 스토어 주소 붙여넣기만 |
| 2 | 다운로드된 `urls.txt`를 AHK 폴더로 옮기기 | 자동 (작업 DB에 바로 저장) |
| 3 | 크롬 줌 100%, 창 위치, 이미지 잘라두기 | **불필요** (화면 인식 안 씀, 7절 참고) |
| 4 | F8 검사, F1 시작, 툴팁으로 진행 확인 | GUI의 ▶ 시작, 별도 진행 창 |
| 5 | 1차 끝나면 셀업 엑셀 내보내기 → 대조 스크립트 | 1차 중 "신호 없음"으로 기록된 것만 **자동으로 2·3차 재시도** |
| 6 | `progress.txt`, `done_urls.txt` 지우고 재실행 | 자동 (회차가 DB 상태로 관리됨) |
| 7 | 끝내 안 되는 URL을 하나씩 열어 삭제 여부 확인 | 자동 판별 → 보고서에 "삭제/판매중지"로 분류 |
| 8 | 스토어 하나 끝나면 다음 스토어 준비 | 여러 스토어를 **대기열**로 넣어두면 밤새 차례로 |
| 9 | 아침에 와서 멈춘 화면 확인 | 캡챠·크롬 종료 시 자동 복구/일시정지 + 알림 |

사람이 하는 일은 **(최초 1회) 전용 크롬에 셀업 확장 설치·로그인**, **(매번) 주소 붙여넣고 시작**, **(선택) 마지막에 셀업 엑셀로 최종 대조** 세 가지만 남는다.

## 2. 핵심 전환: "화면을 보고 누르는" 방식 → "크롬을 직접 조종하는" 방식

v1의 문제 대부분(5-2 ~ 5-11)은 **AHK가 크롬 바깥에서 화면 픽셀을 보고 있기 때문**에 생긴다.
v2는 크롬을 **원격 디버깅 포트(CDP)** 로 띄워 파이썬이 크롬 안쪽을 직접 본다.
(기존 `zzim.py`에서 쓰는 Playwright와 같은 기술. 단, 자동화 표시가 붙는 새 브라우저가 아니라
**일반 크롬을 전용 프로필로 띄우고 거기에 접속**하므로 셀업 확장이 그대로 동작한다.)

| v1 함정 | 원인 | v2에서 |
|---|---|---|
| 5-2 ARMED 오인 (500/500) | 노란 알약 이미지가 비슷 | 버튼의 **글자(텍스트)를 직접 읽음** → `"ARMED"` 문자열 비교라 오인 불가 |
| 5-1 ARMED 1~2초 순간 신호 | 폴링 간격 | 페이지 안에 **변화 감시기(MutationObserver)** 를 심어 바뀌는 순간 기록 → 놓칠 수 없음 |
| 5-3 이전 페이지 버튼 클릭 | 화면에 옛 페이지 잔상 | 이동 완료를 **주소·문서 단위로 확인** (새 문서의 버튼만 찾음) |
| 5-5 포커스(주소창) | Ctrl+L 후 포커스 | 주소창을 안 씀 (`page.goto`), 클릭은 크롬 내부 입력 이벤트 → 포커스 무관 |
| 5-7 저사양 CPU 점유 | 200만 픽셀 ImageSearch | 이미지 검색 없음. DOM 조회는 1ms 미만 |
| 5-8 PNG 크기 / 5-9 듀얼 모니터 / 5-11 줌 | 화면 좌표 의존 | 좌표를 크롬이 계산 → 모니터·배율·줌 무관 |
| 10절 "실행 중 PC 사용 불가" | 창이 가려지면 못 찾음 | 화면에 안 보여도 동작. **창을 최소화해도 됨** (Phase 0에서 확인) |
| 5-10 중복 팝업 | 셀업 본체(윈도우 프로그램) | 그대로 **창 제목으로 감지 → No** (파이썬 win32, 별도 감시 스레드) |

**그대로 유지하는 검증된 규칙**
- 목록에서 클릭하지 않고 상품 URL로 직접 이동 (4절)
- 버튼 발견 후 `CLICK_SETTLE` 대기 (5-4, 셀업 핸들러가 늦게 붙음) — 단, 자동 튜닝 (6절)
- ARMED 미포착 = 실패 아님, 클릭 후 재클릭은 1회만 (5-6)
- 중복은 No (5-10), Escape 금지 (5-12)
- 정렬 분할 수집 금지 (7절)

> ⚠️ 이 전환은 **"셀업 버튼이 페이지 DOM 안에 글자로 들어 있다"** 는 가정에 기대고 있다.
> 그래서 개발 첫 단계(Phase 0)는 이 가정을 확인하는 진단 도구 `sellup_probe.py`다. 결과에 따라 8절의 엔진을 고른다.

## 5. 모듈 상세

### ① URL 수집기 (harvest.py) — v1 콘솔 JS를 그대로 옮김
- 전용 크롬의 스토어 페이지 안에서 `page.evaluate(fetch …)` 실행 → 콘솔에 붙여넣던 것과 **완전히 같은 요청** (쿠키·헤더 동일)
- 규칙은 v1 7절 그대로: `size=80`, 페이지 상한 **3000**, 신규 3페이지 연속 없으면 종료, 1.1~1.8초 랜덤, 429/403이면 60초 쉬고 재시도, 정렬 분할 없음
- 페이지마다 DB에 바로 저장 → 중간에 꺼져도 이어서 수집
- 첫 페이지의 `전체상품(총 N개)` 를 읽어 **예상 개수와 비교**. 수집 결과가 N의 97% 미만이면 경고 (32,000개 잘림 사고 재발 방지)
- 종료 사유 기록: 마지막 도달 / 신규 없음 / 상한 도달 / HTTP 오류

### ② 상품 수집 엔진 (collect_dom.py, 엔진 A 기준)
상품 하나의 처리 순서:
```
1. page.goto(url, wait_until="commit")             주소창·Ctrl+L 없음
2. 이동 확인: page.url 에 상품번호 포함 + 새 문서     (5-3 해결)
3. 페이지 상태 판별 (병렬로 먼저 걸리는 것):
     - 셀업 버튼(텍스트 CAPTURE) 등장 → 4로
     - "판매 중지/삭제된 상품" 문구 → GONE, 클릭 안 함
     - 캡챠/보안확인 화면 → 일시정지 + 알림 (14절)
     - LOAD_WAIT 초과 → LOAD_RETRY 1회 (클릭 전이므로 안전)
4. 결과 감시기 설치: 버튼 글자 변화를 기록하는 MutationObserver
5. CLICK_SETTLE 대기 (자동조절, 기본 1000ms)          (5-4 유지)
6. 버튼 중심 좌표로 실제 마우스 클릭 (CDP 입력)       (5-5 해결)
7. 결과 대기 (최대 ARMED_WAIT):
     - 감시기에 "ARMED" 기록 → ARMED
     - 팝업 감시기가 "기등록 상품 확인" 처리 → DUP (더 안 기다림)
8. 둘 다 없으면 RETRY_CLICK 1회 → 그래도 없으면 NO_SIGNAL
9. DB 저장 → GAP_MIN~GAP_MAX 랜덤 대기 → 다음
```
- **클릭 횟수 상한은 상품당 2회로 코드에서 강제** (DB의 `clicks` 열로 회차를 넘어서도 추적, 9절 금지사항)
- `수집` 과 `ARMED확인` 은 계속 분리 기록. 엔진 A에서는 ARMED가 글자로 판정되므로 두 숫자 차이가 곧 "클릭은 했는데 반응 없음"의 실제 크기다.

### ③ 중복 팝업 감시 (popup.py)
- 별도 스레드가 50ms마다 `FindWindow(None, "기등록 상품 확인")`
- 발견하면 No 버튼 `BM_CLICK` (AHK `ControlClick`과 같은 원리) → 이벤트를 수집 엔진에 전달
- 설정 `DUP_YES` 유지

### ④ 크롬 관리자 (browser.py)
- `chrome.exe --remote-debugging-port=9222 --user-data-dir=<폴더>\chrome_profile` 로 실행
  - 크롬 136부터 기본 프로필로는 디버깅 포트가 막혀 있어 **전용 프로필이 필수**. 셀업 확장은 이 프로필에 한 번 설치
  - 자동화 표시(`navigator.webdriver`)가 붙지 않는 일반 크롬 (`zzim.py` 처럼 Playwright가 직접 띄우는 방식과 다름)
- 접속은 `playwright.chromium.connect_over_cdp`
- **크롬이 죽거나 연결이 끊기면 자동 재시작 → 셀업 확장 로딩 대기 → 다음 상품부터 계속** (5-12 "창이 닫히는 현상" 대응. v1에서는 여기서 밤새 멈췄다)
- 탭은 작업용 1개만 사용. 셀업이 다른 탭을 열면 닫지 않고 무시

### ⑤ 대조기 (reconcile.py)
- **자동 회차**: 1차가 끝나면 `NO_SIGNAL`, `LOAD_FAIL`, `ERROR` 만 2차 대상. 2차 → 3차 동일. `ARMED`, `DUP`, `GONE` 은 제외
  - 회차마다 `CLICK_SETTLE` 을 +300ms 해서 더 천천히 (v1 3차 79%의 원인이 남은 것들이 "느린 페이지"이기 때문으로 추정)
- **엑셀 최종 대조 (선택)**: 셀업에서 내보낸 엑셀을 진행 창에 끌어다 놓으면 `수집URL` 열에서 `/products/(\d+)` 추출 → 차집합 → 누락분을 `CHECKED_MISSING` 으로 표시하고 "누락분만 돌리기" 버튼 활성화
  - 이 경우는 이미 2회 클릭된 상품도 다시 1~2회 클릭 허용 (사람이 확인한 누락이므로)
- 엑셀 읽기는 `openpyxl` (requirements 추가)

## 6. 속도·성공률 자동 조절

v1 원칙 "처리량 최대, 단 성공률 90% 아래로는 안 됨"을 숫자로 만든다.

- 최근 100개 기준 **ARMED율**(= ARMED / (클릭한 것 − DUP)) 을 계속 계산
  - 93% 이상이 200개 유지 → `CLICK_SETTLE` −100ms (하한 500)
  - 88% 미만 → `CLICK_SETTLE` +200ms (상한 2500)
  - 70% 미만 → 즉시 +500ms, 진행 창에 경고
- `GAP` 은 기존 `zzim.py` 의 `Pacer` 와 같은 방식(거절 신호가 없으면 천천히 줄이고, 캡챠·429면 크게 늘림)
- 매 100개마다 `speed.txt` 에 [시각, 개당 초, ARMED율, SETTLE, GAP] 기록 → 다음 튜닝 근거

## 7. 작업 DB (store.py, SQLite)

```sql
products(
  pid        TEXT PRIMARY KEY,   -- 상품번호
  url        TEXT,
  status     TEXT,   -- PENDING / ARMED / DUP / NO_SIGNAL / GONE / LOAD_FAIL / ERROR / CHECKED_MISSING
  round      INT,    -- 마지막으로 시도한 회차
  clicks     INT,    -- 누적 클릭 수 (상한 강제용)
  armed_ms   INT,    -- 클릭 후 ARMED까지 걸린 시간 (튜닝 근거)
  settle_ms  INT,    -- 그때의 CLICK_SETTLE
  updated_at TEXT
)
meta(key, value)     -- 스토어 주소, 총 상품 수(전체상품 N), 수집 종료 사유, 현재 단계
```
- 상품 하나 끝날 때마다 커밋 → `progress.txt` / `done_urls.txt` 역할을 대신하고, "재수집 전 파일 삭제" 같은 수작업이 사라짐
- `urls.txt`, `log.txt` 는 v1 AHK와 호환되는 형식으로 같이 남김 (엔진 C 대비)

## 8. 수집 엔진 3종 — Phase 0 결과로 선택

## 13. Phase 0 진단에서 확인할 것

`sellup_start.bat` 대신 `sellup_probe.bat` 를 실행하면 아래를 자동으로 검사해 `probe_report.txt` 로 저장한다.

1. 전용 프로필 크롬(디버깅 포트)에서 셀업 확장이 정상 동작하는가 (버튼이 뜨는가)
2. 버튼이 어디에 있는가 — 일반 DOM / 열린 shadow root / iframe / 못 찾음(닫힌 shadow root 등)
3. 버튼 글자를 읽을 수 있는가 (`CAPTURE`)
4. CDP 마우스 클릭 후 글자가 `ARMED` 로 바뀌는 과정이 기록되는가 (타임라인 ms 단위)
5. 중복 상품을 클릭했을 때 `기등록 상품 확인` 창이 잡히는가
6. `navigator.webdriver` 값 (false여야 함)
7. 판매중지 상품 URL을 넣었을 때 화면 문구 (GONE_PATTERNS 확정용)

→ 결과 파일을 보내주면 엔진을 확정하고 Phase 1부터 만든다.
