# 스마트스토어 찜 클릭기

네이버 스마트스토어 목록 페이지(80개씩 보기)에서 상품 카드의 찜(♡)을 한 페이지씩 누르는 프로그램입니다. 상품 상세 페이지에는 들어가지 않습니다.

## 설치

```bash
pip install -r requirements.txt
playwright install chrome   # PC에 크롬이 이미 있으면 생략 가능
```

## 실행

`zzim_start.bat`을 더블클릭하면 조작 창이 뜹니다. 크롬보다 항상 위에 떠 있습니다.

- 스토어 주소 칸에 주소를 넣고(여러 개면 한 줄에 하나) **▶ 시작**을 누릅니다.
- **⏸ 일시정지 / ▶ 계속**: 지금 누르는 상품까지 처리하고 멈춥니다.
- **■ 종료**: 작업을 끝냅니다. 다시 시작하면 남은 것부터 이어서 합니다.
- 진행률, 성공·이미 찜·실패·남은 개수, 지금 누르는 상품, 남은 시간이 표시됩니다.

검은 창 모드도 남아 있습니다.

```bash
python zzim.py --console https://smartstore.naver.com/abcstore
python zzim.py --console --file stores.txt
```

옵션
- `--sort-label "최신 등록순"`: 시작할 때 누를 정렬 버튼 글자. 진행하는 동안 순서가 바뀌지 않아야 누락이 없습니다.
- `--delay 600 6000`: 클릭 간격 자동 조절 범위(ms). 1.2초에서 시작해 거절이 없으면 15번마다 10%씩 빨라지고, 거절되면 바로 1.5배 이상 느려집니다. 최소값을 너무 줄이면 네이버가 거절하거나 계정이 제한될 수 있습니다.

## 동작 방식

1. 시크릿 창이 열리면 직접 로그인합니다. 로그인되면 자동으로 시작합니다.
2. "전체상품(총 N개)"를 읽어 페이지 수를 계산합니다.
3. 페이지마다 끝까지 스크롤한 뒤 카드를 한 번에 스캔합니다. 카드 안의 링크 `/products/<ID>`에서 ID를 읽고, 같은 카드 안의 찜 버튼과 짝을 짓습니다.
4. 카드를 화면 좌표순으로 정렬해 5개씩 행으로 묶고 차례로 클릭합니다. 이미 찜한 상품은 건너뜁니다. 클릭이 반영되지 않으면 4초, 8초, 12초 쉬고 다시 시도합니다.
5. 한 페이지가 끝나면 화면 아래 페이지 번호를 눌러 다음 페이지로 갑니다. 상품 목록이 실제로 바뀌었는지 확인합니다.
6. 결과는 `zzim_<스토어명>.csv`에 기록합니다. 중간에 멈춰도 다시 실행하면 처리한 ID는 건너뛰고 이어서 진행합니다.

## 상태 값 (CSV `status`)

| 값 | 의미 |
|---|---|
| clicked | 클릭 후 찜 상태로 바뀐 것을 확인함 |
| already | 실행 전에 이미 찜한 상태였음 |
| clicked? | 클릭은 했지만 상태를 판별하지 못함 |
| fail / error | 실패. 다시 실행하면 재시도함 |

## 처음 실행할 때 확인할 것

- 찜 버튼은 버튼 안에 "찜" 글자(숨김 텍스트 포함)가 있는지로 찾습니다. 찜 상태는 `aria-pressed` 속성이나 "찜하기 취소" 문구로 판별합니다. `clicked?`가 많이 나오면 F12로 버튼 구조를 확인해 `zzim.py`의 `STATE_JS`를 수정하세요.
- `--sort` 값(`st=` 파라미터)은 실제 목록 URL에서 확인하세요.
- 본인 계정 하나로 관심상품을 저장하는 용도로만 사용하세요. 여러 계정으로 찜 수를 부풀리면 네이버 약관 위반입니다.

# 스마트스토어 상품 등록기 (다중 스토어)

수집한 원본 상품(엑셀)을 **인벤토리**에 쌓아 두고, 원본마다 **겹치지 않는 상품명**과 **스토어별 가격**을 붙여 여러 스마트스토어(원본당 최대 3곳)에 **네이버 커머스API**로 등록합니다. 올린 상품은 회차별로 기록해 **새로고침(지우고 다시 올리기)**과 **내리기**를 관리합니다. 조작 화면은 브라우저로 열리며 이 PC(127.0.0.1)에서만 접속됩니다.

`upload_start.bat`을 더블클릭하면 실행됩니다. 필요한 프로그램은 처음에 자동으로 설치됩니다.

## 흐름

```
원본 엑셀 ──▶ 원본 상품(인벤토리) ──▶ 상품명 후보 ──▶ 등록 계획 ──▶ 등록 ──▶ 판매 중 ──▶ 새로고침 / 내리기
  수십만 개      대표 썸네일로 구분      재조합 / AI /     원본당 최대 3곳    33곳 동시            회차 +1     빈 칸이 생김
                 다시 불러오면 갱신      외부 파일 가져오기  이름·가격 배정
```

1. **스토어**: 스토어마다 커머스API 애플리케이션 ID/시크릿을 넣습니다. **여러 개 한 번에 추가**에 엑셀 다섯 칸(이름, ID, 시크릿, 주소, A/S 전화)을 붙여 넣으면 33개를 한 번에 넣을 수 있습니다. **연결 확인**을 누르면 네이버에 이미 있는 상품 수를 받아 와서 남은 자리(기본 한도 1만 개)를 계산합니다.
2. **원본 상품**: 엑셀을 불러오거나 화면에 끌어다 놓습니다. 원본은 **대표 썸네일 주소**로 구분합니다(판매자코드는 스토어마다 바뀌므로 쓰지 않음). 같은 썸네일은 새로 추가하지 않고 내용만 갱신합니다. 썸네일이 없으면 상세 이미지, 그것도 없으면 상품명으로 구분합니다. 불러오면서 바로 검사해 등록 가능 / 경고 / 오류로 나눕니다.
3. **상품명 후보**: 원본마다 쓸 이름을 미리 만들어 둡니다.
   - 재조합: 원본 상품명의 단어를 고르고 순서를 바꿉니다. 무료·즉시. 단어가 적은 상품은 다 못 채울 수 있습니다.
   - AI: Claude API로 원본을 보고 새로 짓습니다(설정에서 API 키·모델). 화면에서 예상 비용을 보여 줍니다.
   - 가져오기: 외부 AI 도구에서 만든 파일을 **상품명 파일 가져오기**로 넣습니다. 원본을 찾는 열(`썸네일`이 가장 정확, 없으면 원본 엑셀의 `판매자코드`나 `원본상품명`)과 `상품명`이 들어간 열(여러 개 가능)이 있으면 됩니다. 한 칸에 여러 이름을 줄바꿈이나 `|`로 넣어도 됩니다.
4. **등록 계획**: 원본을 고르고(조건에 맞는 전체도 가능) **스토어에 올리기 계획**을 누릅니다.
   - 원본 하나는 **최대 3곳**(설정)까지만 올라갑니다. 내린 스토어는 세지 않습니다.
   - 원본마다 N곳이 되도록 골고루, 또는 빈 칸을 모두 채우기 (남은 자리가 많은 스토어부터).
   - 전에 내렸던 스토어에 다시 계획하면 같은 줄이 다음 회차로 살아납니다(같은 이름·가격).
   - 이름은 원본마다 안 쓴 후보에서 하나씩 씁니다(가져옴 → AI → 재조합 순). 모자라면 재조합으로 자동으로 채웁니다.
   - 가격은 스토어마다 원본가 ±3%(설정) 안에서 정하고 100원 단위로 맞춥니다. 같은 상품·같은 스토어는 언제 계획해도 같은 가격입니다.
   - 같은 원본은 한 스토어에 한 번만 올라가고, 스토어 한도를 넘는 건은 만들지 않습니다.
5. **등록**: 스토어·계획으로 거르고 **시작**. 여러 스토어를 나란히 돌리고, 스토어별 진행, 남은 시간, 실패 원인을 보여 줍니다. 일시정지·중단하면 남은 건은 대기로 돌아가고, 실패 건은 다시 시작하면 재시도합니다. **대기·실패 건 계획 취소**를 하면 쓰던 이름이 다시 후보로 돌아갑니다.

## 같은 원본이 여러 스토어에 있을 때

- **판매자 관리코드**를 프로그램이 스토어마다 만들어 등록합니다: `스토어코드-원본번호-회차` (예: `S07-0012345-2` = 스토어 S07, 원본 #12345, 2번째 등록). 스마트스토어센터에서 이 코드로 검색하면 어느 원본의 몇 번째 등록인지 바로 압니다. 형식은 설정에서 바꿀 수 있습니다.
- **원본 상품** 화면의 '스토어 칸'에 원본마다 3칸이 있고, 들어간 스토어 코드가 상태 색으로 표시됩니다(판매 중 초록, 대기 회색, 실패 빨강, 새로고침 대기 파랑, 내리기 대기 주황). 빈 칸은 점선입니다. 위의 칸으로 '아직 0곳 / 1~2곳 / 3곳 다 참'을 거릅니다.
- **등록** 화면의 각 줄에는 같은 원본이 몇 곳에 있는지 표시되고, 줄을 누르면 같은 원본의 다른 스토어 등록과 지난 회차가 보입니다.

## 새로고침과 내리기

- **새로고침**: 판매 중인 건을 네이버에서 지우고 같은 내용(같은 이름·가격, 설정으로 새 이름)으로 다시 올립니다. 회차가 1 오르고 판매자 관리코드 끝 숫자가 바뀝니다. 지운 회차는 '지난 회차'에 남습니다.
- **내리기**: 네이버에서 지웁니다. 원본의 칸이 비어 다른 스토어(또는 같은 스토어)에 다시 계획할 수 있고, 스토어 자리도 돌아옵니다.
- 쓰는 법: 등록 화면에서 **올린 날**(7·30·60·90일 넘음)과 **판매 중**으로 거르고, 고르거나 '조건에 맞는 전체 고르기' → **새로고침 예약** / **내리기 예약** → **시작**. 예약은 **대기·실패 취소**로 되돌릴 수 있습니다.
- 스토어 화면과 한눈에 보기에서 스토어마다 판매 중·대기·실패·내림 수와 가장 오래된 등록이 며칠 전인지 보입니다.
- 결과 CSV에 관리코드, 회차, 올린 날, 원본 번호가 들어갑니다.

## 상품명 중복 방지

모든 상품명은 띄어쓰기·기호·대소문자를 빼고 비교해서, **33개 스토어 전체에서** 같은 이름이 두 번 나오지 않습니다(데이터베이스 UNIQUE 제약). 재조합은 같은 원본의 다른 이름과 단어 구성이 85% 이상 같거나 앞 두 단어가 같으면 버립니다. 원본 상품명 자체는 기본으로 쓰지 않습니다(원본 스토어와 같은 이름이 되므로, 설정에서 바꿀 수 있음).

## 속도

- 네이버 호출 한도는 스토어(애플리케이션)마다 따로라서 스토어를 나란히 돌립니다. 기본은 33곳 동시, 스토어당 2건.
- 대표·추가 이미지는 스토어마다 네이버에 올려야 하지만, 한 번 내려받은 이미지는 디스크(`data/imgcache`, 기본 5GB)에 보관해 다시 받지 않습니다.
- 상세 이미지가 이미 네이버 이미지 서버(`pstatic.net`) 주소면 그대로 둡니다(설정에서 바꿀 수 있음). 다른 주소의 상세 이미지는 한 번만 올리고 모든 스토어가 같이 씁니다.
- 실제 등록 기록이 쌓이면 예상 시간을 그 평균으로 계산합니다. **실행 기록** 화면에서 1건당 시간과 1만 건 예상 시간을 볼 수 있습니다.

시험 결과(네이버 접속 없이 흉내 낸 시연 모드, 이 저장소의 개발 환경): 원본 10만 개 불러오기 약 47초(엑셀 읽기는 별도로 초당 약 1,300줄), 재조합 이름 28만 개 약 38초, 등록 28만 건 계획 약 11초, 목록 화면 0.2초 이내. 데이터베이스는 원본 10만 개에 약 670MB.

## 엑셀 열 → 등록 항목

| 엑셀 열 | 등록 항목 |
|---|---|
| 판매자코드 | 원본 구분(같으면 갱신), 판매자 관리코드 |
| 상품명 | 원본 상품명 (등록에는 후보 중 하나를 씀) |
| 판매가 / 할인가 | 판매가(스토어별 조정). 할인가가 있으면 같은 비율로 즉시할인 |
| 재고수, 판매상태 | 재고, 판매중/판매중지 |
| 썸네일 | 첫 장 대표이미지, 나머지 추가이미지(최대 9장) |
| 상세설명 | 상세페이지 HTML |
| 카테고리 | `대>중>소>세` 이름으로 카테고리 번호를 찾음 |
| 옵션상품 | 조합형 옵션 그대로 |
| 브랜드 / 제조사 / 모델명 | 네이버쇼핑 검색정보, 상품정보제공고시 |
| 원산지 | 원산지 코드 + 수입자 |
| 인증 | KC 인증 대상 제외 정보 |
| 배송비 | 0이면 무료배송, 아니면 선결제 유료배송 |

## 주의

- 상품정보제공고시는 모든 상품을 '기타 재화'로 등록합니다.
- 같은 상품을 자주 지우고 다시 올리는 것은 네이버 검색 정책에서 어뷰징으로 볼 수 있습니다. 새로고침 주기는 정책을 확인하고 정하세요.
- 프로그램 밖(스마트스토어센터)에서 지운 상품은 프로그램이 알지 못합니다. 스토어 화면의 **연결 확인**으로 네이버 상품 수를 다시 받으면 남은 자리 계산은 맞춰집니다.
- 같은 원본을 여러 스토어에 올릴 때 네이버는 상품명뿐 아니라 이미지·상세페이지로도 같은 상품인지 판단할 수 있습니다. 상품명만 바꾼다고 중복 판정을 피한다는 보장은 없습니다.
- 다른 판매자의 사진·상세페이지를 허락 없이 가져와 등록하면 저작권 침해로 상품이 삭제되거나 제재될 수 있습니다.

```

  excel.py      엑셀/CSV를 한 줄씩 읽기
```
