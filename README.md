# 스마트스토어 찜 클릭기

네이버 스마트스토어 목록 페이지(80개씩 보기)에서 상품 카드의 찜(♡)을 한 페이지씩 누르는 프로그램입니다. 상품 상세 페이지에는 들어가지 않습니다.

## 설치

```bash
pip install -r requirements.txt
playwright install chrome   # PC에 크롬이 이미 있으면 생략 가능
```

## 실행

`zzim_start.bat`을 더블클릭하면 조작 창이 뜹니다. 크롬보다 항상 위에 떠 있습니다.

- 스토어 주소 칸에 주소를 넣고(여러 개면 한 줄에 하나) **▶ 시작**을 누릅니다.
- **⏸ 일시정지 / ▶ 계속**: 지금 누르는 상품까지 처리하고 멈춥니다.
- **■ 종료**: 작업을 끝냅니다. 다시 시작하면 남은 것부터 이어서 합니다.
- 진행률, 성공·이미 찜·실패·남은 개수, 지금 누르는 상품, 남은 시간이 표시됩니다.

검은 창 모드도 남아 있습니다.

```bash
python zzim.py --console https://smartstore.naver.com/abcstore
python zzim.py --console --file stores.txt
```

옵션
- `--sort-label "최신 등록순"`: 시작할 때 누를 정렬 버튼 글자. 진행하는 동안 순서가 바뀌지 않아야 누락이 없습니다.
- `--delay 600 6000`: 클릭 간격 자동 조절 범위(ms). 1.2초에서 시작해 거절이 없으면 15번마다 10%씩 빨라지고, 거절되면 바로 1.5배 이상 느려집니다. 최소값을 너무 줄이면 네이버가 거절하거나 계정이 제한될 수 있습니다.

## 동작 방식

1. 시크릿 창이 열리면 직접 로그인합니다. 로그인되면 자동으로 시작합니다.
2. "전체상품(총 N개)"를 읽어 페이지 수를 계산합니다.
3. 페이지마다 끝까지 스크롤한 뒤 카드를 한 번에 스캔합니다. 카드 안의 링크 `/products/<ID>`에서 ID를 읽고, 같은 카드 안의 찜 버튼과 짝을 짓습니다.
4. 카드를 화면 좌표순으로 정렬해 5개씩 행으로 묶고 차례로 클릭합니다. 화면에 이미 찜으로 표시된 상품은 누르지 않고 건너뜁니다(이전 기록 파일은 보지 않음). 클릭이 반영되지 않으면 4초, 8초, 12초 쉬고 다시 시도합니다.
5. 한 페이지가 끝나면 화면 아래 페이지 번호를 눌러 다음 페이지로 갑니다. 상품 목록이 실제로 바뀌었는지 확인합니다.
6. 한 번 실행하는 동안 **'반영 안 됨'이 누적 3번** 나오면 바로 멈추고 알림을 보냅니다(`--max-rejects`로 횟수 변경, 0이면 끔). 계속 누르면 계정 보호조치로 이어질 수 있기 때문입니다. 크롬 창이 닫혀도 바로 멈춥니다.
7. 조작 창 아래 **텔레그램 알림** 칸에 봇 토큰과 채팅 ID를 넣으면, 작업이 끝나거나 멈출 때 사유와 진행 상황을 메시지로 보냅니다. 값은 `zzim_settings.json`에 저장됩니다.
8. 스토어 하나를 마칠 때마다(완료·중단·오류 모두) **`zzim_report.csv`** 보고서에 한 줄씩 누적합니다. 시작·종료 시각, 소요 시간, 네이버 아이디, 스토어, 전체 상품 수, 이번 성공·이미 찜·실패, 반영 안 됨 횟수, 누적 완료, 남은 개수, 진행률, 결과, 사유가 들어갑니다. 조작 창의 **📊 보고서 열기**로 엑셀에서 바로 열 수 있습니다. 네이버 아이디는 로그인 화면에 입력한 값을 자동으로 적고(비밀번호는 읽지 않음), 조작 창에 직접 적을 수도 있습니다. 보고서가 엑셀에서 열려 있으면 `zzim_report_미기록.csv`에 대신 기록합니다.
9. 상품별 기록은 `zzim_<스토어명>.csv`에 남깁니다. **기록일 뿐이고 건너뛰기 판단에는 쓰지 않습니다.** 다시 실행하면 처음 페이지부터 화면의 찜 상태를 다시 확인하므로, 계정이 바뀌거나 직접 찜을 해제한 경우에도 실제 상태대로 처리됩니다. 보고서의 '누적 완료'도 그 실행에서 화면으로 확인한 찜 개수입니다.

## 상태 값 (CSV `status`)

| 값 | 의미 |
|---|---|
| clicked | 클릭 후 찜 상태로 바뀐 것을 확인함 |
| already | 화면에서 이미 찜 상태로 확인되어 누르지 않음 |

찜 상태를 화면에서 판별할 수 없으면 누르지 않고 멈춥니다. 찜 버튼은 누를 때마다 켜짐/꺼짐이 바뀌어서, 판별 없이 누르면 이미 된 찜이 해제될 수 있기 때문입니다.
| fail / error | 실패. 다시 실행하면 재시도함 |

## 처음 실행할 때 확인할 것

- 찜 버튼은 버튼 안에 "찜" 글자(숨김 텍스트 포함)가 있는지로 찾습니다. 찜 상태는 `aria-pressed` 속성이나 "찜하기 취소" 문구로 판별합니다. `clicked?`가 많이 나오면 F12로 버튼 구조를 확인해 `zzim.py`의 `STATE_JS`를 수정하세요.
- `--sort` 값(`st=` 파라미터)은 실제 목록 URL에서 확인하세요.
- 본인 계정 하나로 관심상품을 저장하는 용도로만 사용하세요. 여러 계정으로 찜 수를 부풀리면 네이버 약관 위반입니다.

# 셀업 자동 수집 (sellup_ahk/sellup_v21.ahk)

잘 돌아가던 AutoHotkey v8 스크립트를 기준으로 스토어 목록 조작 창, 속도 단계, 스토어 → 주소 모으기 → 수집 자동 흐름을 붙인 버전입니다. 수집 동작 자체(주소 이동 → CAPTURE 찾기 → 대기 → 고정 오프셋 클릭 → 중복 팝업 No)는 v8과 같습니다.

## 준비

`sellup_v21.ahk`를 v8이 있던 폴더(`img\capture.png`, `img\armed.png`, `done_urls.txt`가 있는 곳)에 넣습니다.

## 조작 창

**스토어 목록**: 스토어마다 한 줄씩, 체크한 스토어만 작업합니다.

| 칸 | 뜻 |
|---|---|
| 모은 주소 | `urls.txt`에 있는 그 스토어 상품 주소 수 |
| 완료 | 수집했거나 중복으로 건너뛴 수 |
| 실패 | 실패로 기록된 수 |
| 남음 | 아직 안 한 수 |
| 상태 | 주소 없음 / 주소 모음 / 모으는 중 12쪽 · 960개 / 수집 중 / 이어하기 가능 / 수집 완료 / 주소 일부만 모음 |

**버튼**

- **추가 / 선택 삭제 / 전체 체크**: 스토어 주소를 붙여넣어 목록에 올리거나 뺍니다. 삭제는 목록에서만 빼고 모아 둔 주소와 기록 파일은 그대로 둡니다.
- **▶ 수집 시작 (F1)**: 체크한 스토어마다, 주소가 없으면 먼저 모으고 남은 상품을 수집합니다. 이미 주소를 모은 스토어는 다시 모으지 않고 바로 이어서 수집합니다.
- **주소만 모으기**: 수집 없이 주소만 모읍니다.
- **이미 모은 스토어도 주소 다시 모으기**: 켜면 주소가 있는 스토어도 다시 훑어 신상품을 추가합니다.
- **⏸ 일시정지 (F4) / ■ 중단**: 중단해도 진행 상황은 저장되고, 다시 시작하면 남은 것부터 합니다. 주소를 모으는 도중 중단하면 그때까지 모은 주소를 저장하고 "주소 일부만 모음"으로 표시하며, 다음에 시작할 때 그 스토어는 주소를 다시 모읍니다.

F2는 즉시 종료, F3은 단발 테스트(v8과 동일)입니다. 조작 창이 오른쪽 아래 CAPTURE 버튼을 가리지 않게 두세요.

## 속도 단계

| 단계 | 상품 사이 간격 | 그 밖의 차이 |
|---|---|---|
| 안전 | 3~6초 | v8과 모든 대기시간이 같음 |
| 보통 | 1~2초 | 주소 입력 대기, ARMED 뒤 대기를 줄임 |
| 빠름 (기본) | 0.3~0.8초 | 위에 더해 클릭 전 대기 1.2초 → 1초, 키 입력 간격 축소 |
| 최고속 | 0~0.2초 | 클릭 전 대기 0.9초, ARMED 이미지 확인 생략(클릭 후 0.7초간 중복 팝업만 확인) |

속도 줄 끝의 `[이동 · 대기 · 클릭후]`는 상품 하나에서 주소 입력, 페이지 대기, 클릭 후 감시에 걸린 평균 초입니다. 어느 구간이 느린지 보고 스크립트 위쪽 `PRESETS` 표의 숫자를 조정하면 됩니다. 단계를 올릴 때는 50개쯤 돌려 셀업에 실제로 쌓인 개수와 조작 창의 숫자를 비교하세요.

## 파일

- `stores.txt`: 스토어 목록과 체크 상태
- `urls.txt`: 모은 상품 주소 전체
- `done_urls.txt`: 수집(또는 중복으로 건너뜀)한 주소. 여기 있는 주소는 다시 들어가지 않습니다.
- `fail_urls.txt`: 실패한 주소. 다시 시도하려면 이 파일을 지웁니다.
- `harvested_stores.txt`: 스토어별 주소 모은 기록
- `log.txt`: 전체 기록

## 주소 모으기 방식

스토어 페이지를 열고 주소창에 `javascript:` + 스크립트를 넣어 실행합니다. 스크립트는 목록(80개씩)을 한 쪽씩 `fetch`로 받아 `/products/<번호>`를 모으고, 진행 상황을 탭 제목(`HARVEST 12p / 960`)에 표시합니다. 조작 창은 이 제목을 읽어 스토어 목록의 상태 칸에 보여 주고, 끝나면 화면에 뜬 주소 목록을 복사해 `urls.txt`에 추가합니다. 자동 실행이 안 되면 경고음과 함께 5분간 기다리므로, 크롬에서 F12 → Console에 Ctrl+V, Enter를 하면 이어서 진행됩니다(스크립트는 클립보드에 복사되어 있음).
