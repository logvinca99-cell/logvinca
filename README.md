# 스마트스토어 찜 클릭기

네이버 스마트스토어 목록 페이지(80개씩 보기)에서 상품 카드의 찜(♡)을 한 페이지씩 누르는 프로그램입니다. 상품 상세 페이지에는 들어가지 않습니다.

## 설치

```bash
pip install -r requirements.txt
playwright install chrome   # PC에 크롬이 이미 있으면 생략 가능
```

## 실행

`zzim_start.bat`을 더블클릭하면 조작 창이 뜹니다. 크롬보다 항상 위에 떠 있습니다.

- 스토어 주소 칸에 주소를 넣고(여러 개면 한 줄에 하나) **▶ 시작**을 누릅니다.
- **⏸ 일시정지 / ▶ 계속**: 지금 누르는 상품까지 처리하고 멈춥니다.
- **■ 종료**: 작업을 끝냅니다. 다시 시작하면 남은 것부터 이어서 합니다.
- 진행률, 성공·이미 찜·실패·남은 개수, 지금 누르는 상품, 남은 시간이 표시됩니다.

검은 창 모드도 남아 있습니다.

```bash
python zzim.py --console https://smartstore.naver.com/abcstore
python zzim.py --console --file stores.txt
```

옵션
- `--sort-label "최신 등록순"`: 시작할 때 누를 정렬 버튼 글자. 진행하는 동안 순서가 바뀌지 않아야 누락이 없습니다.
- `--delay 600 6000`: 클릭 간격 자동 조절 범위(ms). 1.2초에서 시작해 거절이 없으면 15번마다 10%씩 빨라지고, 거절되면 바로 1.5배 이상 느려집니다. 최소값을 너무 줄이면 네이버가 거절하거나 계정이 제한될 수 있습니다.

## 동작 방식

1. 시크릿 창이 열리면 직접 로그인합니다. 로그인되면 자동으로 시작합니다.
2. "전체상품(총 N개)"를 읽어 페이지 수를 계산합니다.
3. 페이지마다 끝까지 스크롤한 뒤 카드를 한 번에 스캔합니다. 카드 안의 링크 `/products/<ID>`에서 ID를 읽고, 같은 카드 안의 찜 버튼과 짝을 짓습니다.
4. 카드를 화면 좌표순으로 정렬해 5개씩 행으로 묶고 차례로 클릭합니다. 이미 찜한 상품은 건너뜁니다. 클릭이 반영되지 않으면 4초, 8초, 12초 쉬고 다시 시도합니다.
5. 한 페이지가 끝나면 화면 아래 페이지 번호를 눌러 다음 페이지로 갑니다. 상품 목록이 실제로 바뀌었는지 확인합니다.
6. 결과는 `zzim_<스토어명>.csv`에 기록합니다. 중간에 멈춰도 다시 실행하면 처리한 ID는 건너뛰고 이어서 진행합니다.

## 상태 값 (CSV `status`)

| 값 | 의미 |
|---|---|
| clicked | 클릭 후 찜 상태로 바뀐 것을 확인함 |
| already | 실행 전에 이미 찜한 상태였음 |
| clicked? | 클릭은 했지만 상태를 판별하지 못함 |
| fail / error | 실패. 다시 실행하면 재시도함 |

## 처음 실행할 때 확인할 것

- 찜 버튼은 버튼 안에 "찜" 글자(숨김 텍스트 포함)가 있는지로 찾습니다. 찜 상태는 `aria-pressed` 속성이나 "찜하기 취소" 문구로 판별합니다. `clicked?`가 많이 나오면 F12로 버튼 구조를 확인해 `zzim.py`의 `STATE_JS`를 수정하세요.
- `--sort` 값(`st=` 파라미터)은 실제 목록 URL에서 확인하세요.
- 본인 계정 하나로 관심상품을 저장하는 용도로만 사용하세요. 여러 계정으로 찜 수를 부풀리면 네이버 약관 위반입니다.

# 스마트스토어 상품 등록기 (다중 스토어)

수집한 원본 상품(엑셀)을 **인벤토리**에 쌓아 두고, 원본마다 **겹치지 않는 상품명**과 **스토어별 가격**을 붙여 여러 스마트스토어(원본당 최대 3곳)에 **네이버 커머스API**로 등록합니다. 올린 상품은 회차별로 기록해 **최신화(지우고 다시 올리기)**와 **내리기**를 관리합니다. 조작 화면은 브라우저로 열리며 이 PC(127.0.0.1)에서만 접속됩니다. 화면 맨 위 제목·버튼 줄과 목록의 선택·쪽 넘기기 막대는 아래로 내려도 위에 붙어 있습니다.

`upload_start.bat`을 더블클릭하면 실행됩니다. 필요한 프로그램은 처음에 자동으로 설치됩니다.

## 흐름

```
원본 엑셀 ──▶ 원본 상품(인벤토리) ──▶ 다른 스토어로 복사 ──▶ 복사본(스토어 고르기) ──▶ 상품명 바꾸기 ──▶ 등록 ──▶ 최신화 / 내리기
  수십만 개      바꾸지 않는 원본 DB      고른 스토어 1~2곳에       이름 변경 필요 거르기      AI 맥락 키워드 /    스토어별     회차 +1
                 걸러서 고름              원본당 최대 2회          줄마다 바로 바꾸기         AI로 짓기 / 셔플
```

1. **스토어**: **사업자별로 묶어** 보여 줍니다(사업자 하나에 스토어 최대 3개). 사업자 이름을 누르면 접고 펼치고, **⠿ 손잡이를 끌어** 사업자·스토어 순서를 바꾸거나 스토어를 다른 사업자로 옮깁니다(복사·복사본 화면의 스토어 순서도 같이). 카드마다 **스토어 ↗**(그 스마트스토어 새 창, 스토어 주소는 '수정'에서 넣거나 연결 확인 때 자동으로 채움)·**판매자센터 ↗** 버튼이 있습니다(한눈에 보기·복사본 화면도). 카드 위 **해외 | 국내** 버튼으로 지금 출고 형태를 표시합니다(해외 파란색 · 국내 초록색, 누른 것을 다시 누르면 지움, 표시만 하고 등록 내용은 바꾸지 않음). 스토어는 사업자 칸 안에 **카드**로 나란히 놓이고(한눈에 보기도 같은 모양), 카드마다 사용량 막대에 네이버 상품·**고구마(전시중지)**·등록 대기·남은 자리가 보입니다. 고구마 상품도 한도를 차지하며, **연결 확인**은 네이버 상품을 처음부터 끝까지 넘겨 보며 상태(판매 중·판매중지·품절·승인대기 …)를 하나씩 세므로 상품이 많으면 몇십 초 걸립니다. 전시 상태(전시 중·**전시중지**)도 같이 셉니다. 센 결과는 카드에 "네이버 N개: 판매 중 x · 판매중지 y … · 전시중지(고구마) z"로 남으니 판매자센터 숫자와 맞춰 보세요. **전시중지** 수가 고구마로 자동으로 들어가고(판매중지는 고구마가 아님), 다르면 ✎로 직접 입력합니다(비우면 자동). 스토어마다 커머스API 애플리케이션 ID/시크릿을 넣습니다(여러 개 한 번에 추가 가능, 사업자는 스토어 수정에서 고름). **템플릿**에서 스토어마다 상세 상단·하단(이미지 + HTML), 상세 옵션표 모양·강조색, 출고지·반품지(판매자센터 주소록 번호, "네이버 주소록 불러오기"로 골라 넣음, 비우면 판매자센터 기본 주소), 관부가세(목록에서 고름: 미포함·포함·부과 대상 아님, 고르지 않으면 설정 공통값), 스토어 가격 차이 %, 표시 할인율 %를 정합니다.
   - **스토어 메모**: 카드마다 메모 칸이 있어 이 스토어를 무슨 상품으로 채웠는지, 앞으로 어떻게 할지 적어 둡니다. 적는 대로 저장되고(수정 창에서도 고침) 나만 봅니다.
   - **업무 메모**: 한눈에 보기 맨 위 메모 칸에 매일 할 일·하고 있는 일을 적어 둡니다. 적는 대로 저장됩니다.
2. **원본 상품**: 가지고 있는 원본 DB 전체입니다. 원본은 바꾸지 않습니다. 중복 기준은 **상품명이 완전히 같음**(띄어쓰기·순서까지, 앞뒤 공백만 무시)입니다(대표 이미지 주소는 기준이 아님). 엑셀을 다시 불러와도 **원본을 덮어쓰지 않습니다** — 상품명이 같은 원본이 이미 있거나 파일 안에 같은 상품명이 또 나오면 **'상품명 중복'으로 넣지 않고**, 넣기 전 확인 창에 수·줄·겹치는 원본을 보여 주며 **중복 목록 받기(CSV)**로 받을 수 있습니다. 이미 있는 원본의 가격은 **기준 가격 수정**으로 고칩니다.
   **대표 이미지 주소 겹침 확인**: 원본 엑셀 불러오기·상세 정리 엑셀 올리기 때 상품명은 다른데 대표 이미지 주소가 이미 있는 원본(또는 같은 파일 앞줄)과 같은 줄을 세서 창을 띄웁니다 — 몇 개인지·예시를 보고 **포함해서 저장** 또는 **겹치는 상품은 버리고 저장**을 고릅니다(가격 칸 확인과 같은 창).
   - 거르기: 상품명 검색, **기준 가격 구간**, **복사 횟수(미복사 / 1회 / 2회)**, 경고·오류, 특정 스토어에 없는 것. 걸러진 결과는 '조건에 맞는 N개 모두 선택'으로 한 번에 고릅니다.
   - 위에 붙는 막대: 선택 상태, 할 일 버튼(AI 맥락 키워드 받기 · 다른 스토어로 복사), 몇 개씩 보기, 쪽 이동(위·아래 모두).
3. **다른 스토어로 복사**: 스토어를 1~2곳 고르면 고른 원본을 **그 스토어에 그대로** 복사합니다. 원본 하나는 최대 2회(내린 것은 세지 않음)라, 이미 그 스토어에 있거나 2회를 넘는 원본은 빼고 몇 개 뺐는지 알려 줍니다. 가격은 스토어 템플릿의 스토어 가격 차이 %와 ±3%(설정), 100원 단위 올림. AI 맥락 이름 후보가 있으면 바로 붙고, 없으면 '이름 변경 필요'.
4. **복사본**: 먼저 **스토어를 고릅니다**(스토어별 복사본·이름 변경 필요·대기·판매 중·실패 수). 그 스토어의 복사본만 보입니다.
   - 줄마다 **상품명 바꾸기**, **원본 보기**, 같은 원본이 있는 **다른 스토어로 가기** 버튼.
   - 등록 상품명을 원본과 색으로 비교합니다: 원본과 같은 자리 / 자리만 바뀜(셔플) / AI 단어 / 직접 넣은 단어 / 빠진 원본 단어(취소선).
   - 판매자 관리코드는 그대로이고, 상품명만 바꿉니다.
5. **상품명 바꾸기** (세 가지):
   - **AI 맥락 키워드** (기본): 아래 '상품명: 맥락 키워드 조립'.
   - **AI로 짓기**: AI가 이름 전체를 새로 짓습니다.
   - **셔플** (AI 안 씀): 앞 N단어(직접 정함, 기본 3)를 고정하고 나머지 단어 순서를 섞습니다. 넣을 단어를 적으면 그 단어도 고정 단어 뒤에서 함께 섞입니다. 50자를 넘으면 넣은 단어는 남기고 원본 단어를 뺍니다.
   - 모든 이름은 금지어·상표와 **33개 스토어 중복**을 검사합니다. 이름을 안 바꾼 복사본은 등록에서 빠집니다.
6. **등록**: 복사본 화면(그 스토어)의 시작 칸에서 **범위**(이 스토어 전체 / 고른 것만 / 지금 보이는 조건만)와 **종류**(등록 · 최신화 · 내리기 · 실패 재시도, 각각 건수 표시)를 고르고 **▶ 시작**. 상품명을 안 바꾼 새 등록은 어느 범위에서도 올리지 않습니다. 상세페이지 앞뒤에 그 스토어의 상단·하단을 붙이고(상단·하단 이미지는 그 스토어로 한 번 올려 두고 다시 씀), 관부가세 코드·표시 할인율을 넣어 보냅니다.

## 상세 정리 (셀업 엑셀 → 정리 → 원본)

흐름: **셀업 엑셀 → 상세 정리 → 원본 상품 → 상품명 변경 → 복사·등록**. 왼쪽 메뉴 **상세 정리**(원본 상품 위)에서 합니다.
정리하는 동안의 상품은 **정리함**에만 있고 원본 상품에는 들어가지 않습니다. 엑셀을 올릴 때마다 정리함 묶음이 하나 생기고, 화면 위 칸에서 묶음을 고릅니다.

1. **엑셀 올리기**: 이 화면에 엑셀을 끌어다 놓거나 눌러서 고릅니다(이 화면에서는 '무엇으로 불러올까요?'를 묻지 않음). 올릴 때 자동으로(체크로 끄고 켬):
   가격을 **고객 결제가 한 칸**으로(판매가 − 할인가, 할인가 비움) · 상품코드(판매자코드) 비우기 · 브랜드·제조사·모델명·원산지를 '상세페이지 참조'로. 아래 ②에서 '다음에도 자동으로 빼기'로 기억한 이미지도 바로 뺍니다.
2. **공통 이미지 찾기·제거**: N개(기본 10) 이상 상품에 똑같이 들어간 이미지(상단·하단 공지 배너 등)를 모아 보여 줍니다. 고른 것을 모든 상품에서 지우고, **다음에 올리는 엑셀에서도 자동으로 빼기**를 켜면 기억합니다(기억한 목록에서 '그만 빼기').
3. **전화번호 찾기·제거**: 상세 글자·옵션명·상품명에서 찾습니다. **빨강** = 010형(기본 선택), **노랑** = 의심(지역번호·15xx·숫자 묶음 — 치수·날짜일 수 있어 직접 확인). 사진 속 번호는 못 찾습니다.
4. **상세 미리보기·편집**: 행 번호(제목 1행, 첫 상품 2행)로 엽니다. 이미지를 **클릭해서 선택 → Delete**로 지우고, 글자는 **클릭해서 바로 고칩니다**. Ctrl+Z로 되돌리고, **이 상품에 반영**을 눌러야 저장됩니다. **처음 상세로 되돌리기**는 엑셀에서 올린 그대로로. 다른 단계 결과의 'N행'을 누르면 여기서 열립니다.
5. **잘린·빈 상세**: 엑셀 칸 글자수 한도(32,767자)에 걸려 중간에 잘린 상세와 완전히 빈 상세를 찾아 지웁니다.
6. **빈 칸 상품**: 상품명·판매가·상세설명(·썸네일·카테고리)이 빈 상품을 찾아 지웁니다.
7. **카테고리 검사·수정 · 생활화학 판정**: 최신 네이버 카테고리 목록과 대조해 형식 이상·목록에 없음(폐지·오타)·중간 분류를 보여 주고 **바꾸기**로 그 카테고리 상품을 한꺼번에 바꿉니다. **생활화학 판정**은 아래 '생활화학·살생물제' 참고 — 화학제품·애매는 **생활화학 보류**로 빠져 원본에 넣지 않습니다.
8. **원본 상품으로 넣기 / 새 엑셀로 저장**: 정리 중인 상품만 원본으로 넣습니다(보류·지운 것 제외, 상품명이 완전히 같은 원본이 이미 있으면 '상품명 중복'으로 넣지 않고 정리함에 남김 — 엑셀 올리기 때도 중복 줄은 정리함에 넣지 않음). **새 엑셀로 저장**은 올린 엑셀과 같은 열로 `원래이름_수정.xlsx`를 내려받습니다.

지운 상품은 위 **지움** 칸을 눌러 되살립니다. 방문 알림·http 동영상 빼기, PC 폭 맞추기, 옵션표 2열 그림은 예전처럼 **올릴 때** 자동으로 합니다.

## 검수 완료 관리 (눈검수 한 것만 새로 올리기)

모든 상품의 **검수 여부**를 원본 기준 하나로 관리합니다. **검수 완료한 원본만 새로 올립니다** — 그 스토어에 **한 번도 안 올린** 새 등록만 막습니다(최신화·다시 올리기·내리기, 최신화가 지운 뒤 실패해서 다시 등록하는 것, 내린 것 다시 올리기는 그대로).
- 검수 완료로 만드는 방법: ① **눈검수**에서 그 쪽을 완료(원본 상품 화면·복사본 화면 어디서든), ② 목록에서 고르거나 전체 선택해서 **[검수 완료로 표시]**(이미 검수한 엑셀 등). **[검수 완료 풀기]**도 있고, 원본 상세(정보 탭)에서 하나씩도 바꿉니다.
- 어디서든 구분: 원본·복사본 줄마다 **검수 완료**(초록)·**미검수**(회색) 표시, 위쪽 칸에 **[검수 완료] [미검수 (새로 못 올림)]** — 누르면 그것만 보여 고를 수 있습니다.
- 복사 창: **'검수 완료한 원본만 복사'**(기본 켬, 고른 것 중 몇 개인지 표시). 끄면 미검수도 복사되지만 새로 올리지는 않습니다.
- 시작(올리기): 미검수 원본의 새 등록은 건너뛰고 '눈검수 안 한 원본이라 새로 올리지 않는 복사본 N건 — 미검수 보기'로 알려 줍니다.

## 눈검수 (원본 상품·복사본 화면)

원본 상품 화면이나 복사본 화면(스토어) 위 **눈검수**를 누르면 **대표 사진만** 그리드로(인스타그램처럼) 봅니다. 원본 상품 화면에서는 원본 전체(또는 거른 조건), 복사본 화면에서는 그 스토어 복사본을 봅니다. 원본에서 지우면 그 원본과 모든 스토어 복사본이 지워집니다. 한 쪽이 **화면에 꽉 차게** 나와 내리지 않아도 다 보이고(창 크기에 맞춰 열 수·사진 크기를 정함), 사진 밑 **남색 칸**에 **상품명 앞 키워드 4개**(띄어쓰기 기준)가 흰 글자로 크게 나옵니다. **금지 단어는 빨강 바탕**, **상표로 등록·출원된 단어는 주황 바탕**입니다. 이 화면에서만 커서가 **크고 형광 연두색**입니다(닫으면 원래대로).
- **클릭** = '삭제 예정'(빨간 테두리·빨간 이름 칸), **한 번 더 누르면 풀림**. **끌기** = 네모 안 여러 장(고른 사진에서 시작하면 풀기), **Shift+클릭** = 범위. 마우스를 올려도 아무것도 안 뜨고, **우클릭**하면 큰 사진과 상품명 전체(원본 이름·관리코드·상태·가격, 삭제 예정으로/풀기, 상품명 복사, 네이버·수집한 곳 바로 가기)가 나옵니다.
- **삭제 예정이 있으면 초록 버튼이 빨간 [✓ 고른 N개 삭제하고 다음 쪽]으로 바뀝니다.** 누르면 확인 창 없이 지우고(원본까지 — 위 '삭제와 휴지통') 이 쪽을 완료로 하고 다음 쪽으로 갑니다. → 키도 같습니다. 판매 이력·잠금이 있는 것은 지우지 않고 남깁니다.
- 쪽을 넘기기 전에 지우고 싶으면 오른쪽 **[지금 삭제]**(확인 창에서 '원본까지'를 끌 수 있음).
- **지운 칸은 눈검수에서 늘 그 자리에 '삭제됨'으로** 남습니다(이전 쪽으로 가도, 닫았다 다시 열어도 — 목록이 당겨지지 않음). **그 칸을 다시 누르면 그 하나만 되살아납니다**(휴지통에 있을 때). '눈검수 안 한 것만'으로 볼 때는 이번에 지운 칸만 남깁니다.
- **되돌리기**: [↶ 되돌리기]로 방금 지운 것을 마지막 것부터 되돌립니다. 판매 중인 것의 네이버 내리기는 **한 쪽 늦게**(그다음 쪽을 완료하거나 닫을 때) 시작하므로, **다음 쪽으로 넘어간 뒤에도** 되돌리면 내리기가 취소되고 원본·복사본(다른 스토어 포함)이 되살아나 완전히 원래대로입니다. 이미 네이버에서 내려간 것은 원본만 되살아나고 복사본은 '내림'으로 남습니다(복사본 화면에서 다시 올리기). 닫기 없이 브라우저를 끄면 미룬 내리기는 대기로 남습니다(시작에서 '내리기').
- 오른쪽 칸(늘 보임): 쪽 번호, 완료 버튼, [이전 쪽](← 키), 삭제 예정 수, [이 쪽 전부]·[모두 풀기]·[지금 삭제], [되돌리기], 오늘 진행, **메모**, 한 쪽 장수, '눈검수 안 한 것만'.
- 한 쪽 장수: 24장(크게) · 40장(보통) · 60장(작게) · 96장(아주 작게) · 150장(한눈에).
- **이어서 시작**: '이 쪽 완료'를 누를 때마다 그 자리를 스토어마다(원본은 따로) 기억합니다. 다음에 열면 멈춘 다음 쪽부터 시작하고 '지난번 이어서 · 몇 시에 멈춤'이 뜹니다([처음부터]로 처음으로). 한 쪽 장수·'안 한 것만'도 같이 기억합니다.
- **메모**: 스토어마다(원본은 따로) 적는 대로 자동 저장(껐다 켜도 남음).
- **오늘 진행**: 오늘 본 것·지운 것, 남은 쪽(건수), 오늘 속도로 남은 예상 시간(쪽을 두 번 넘기면 나옴, 5분 넘게 쉰 시간은 뺌).
- 쪽은 복사본 번호 순이라 지운 만큼 건너뛰는 상품이 없습니다. 완료 표시는 **원본 기준**이라 같은 원본의 다른 스토어 복사본도 '본 것'(✓)으로 나옵니다.
- 범위: 원본 전체 / 이 스토어 복사본 전체(내림 제외), 또는 그 화면에서 거른 조건만.

## 출처 태그 (어디서·언제 가져온 원본인지)

셀업으로 여러 루트에서 원본을 모으므로, 원본마다 **출처 태그**를 붙여 둡니다. 엑셀의 '상품태그'(네이버 검색 태그)와는 다른 것이고 네이버에 보내지 않습니다.

- **불러올 때 붙이기**: 상세 정리 ① 엑셀 올리기, 원본 엑셀 불러오기(버튼·끌어다 놓기) 모두 **출처 태그** 칸이 있습니다. 쉼표로 여러 개, 기본값은 오늘 날짜. 최근 쓴 태그를 누르면 칸에 더해집니다.
  **수집 스토어도 태그로**를 켜면 엑셀 '수집URL'의 스토어 주소 이름(smartstore.naver.com/**zenith77** → `zenith77`, 다른 사이트는 `coupang.com`처럼 사이트 주소)이 붙습니다.
- 상세 정리에서는 묶음마다 태그를 정해 두고(① 아래 '이 묶음의 출처 태그' → 바꾸기), **원본 상품으로 넣을 때** 붙습니다.
- 같은 원본(상품명이 완전히 같음)을 다른 루트로 또 불러오면 태그가 **더해집니다**(지워지지 않음).
- **원본 상품** 화면: 줄마다 태그가 보이고(날짜는 회색), **출처 태그** 거르기 칸(스토어·루트 / 가져온 날 / 태그 없는 원본), 검색 칸에서도 태그로 찾습니다.
  고른 원본 → **출처 태그 달기·빼기**, 원본 상세(서랍) 정보 탭에서 하나씩 달고 ✕로 빼기.
- 위 **출처 태그** 버튼: 모든 태그와 원본 수, 누르면 그 원본만 보기, 이름 바꾸기·지우기(모든 원본에서), **예전에 불러온 원본에도 채우기**(수집URL의 스토어, 처음 불러온 날 — 있는 태그는 그대로 두고 더하기만).

## 기존 상품 가져오기 (이미 스토어에 올린 상품)

다른 방법으로 **이미 스토어에 올려 둔 상품**을 이 프로그램으로 가져옵니다. 원본 상품 화면 위 **기존 상품 가져오기**.
1. 그 스토어에 **올렸던 셀업 엑셀(최종 업로드본)**을 끌어다 놓습니다. **파일 하나 = 스토어 하나**.
2. 미리보기에서 **이 파일을 올렸던 스토어**를 고릅니다(브랜드로 짐작해 미리 골라 둠).
   **뺄 공통 이미지**: 상세 정리 '공통 이미지'와 같은 방식으로, 10개 이상 상품에 똑같이 들어 있는 이미지를 **전부** 보여 줍니다(몇 개 상품에 있는지·상단/하단/가운데). 상품 5% 넘게 들어 있는 것(스토어 상단·하단 배너)과 상세 정리에서 '다음에도 빼기'로 기억한 것은 미리 골라 둡니다. 고른 이미지는 **모든 상품** 상세에서 뺍니다(앞뒤가 조금 다른 상품도 빠짐 — 예전 방식은 상단이 조금 다른 상품 수백 개를 놓쳤음). 이미 있던 원본 상세에서도 고른 배너는 뺍니다.
3. **[맞춰 보기]** → 그 스토어의 네이버 상품 목록을 받아(스토어당 몇 분) **판매자코드**로 맞춰 보고 결과만 보여 줍니다 — **아무것도 바뀌지 않습니다**. 판매자코드가 맞는 줄 %(절반 아래면 '이 스토어 파일이 맞는지 확인' 경고), 새로 연결·이미 연결·스토어에 없어 뺌(원본에 있는 것)·스토어에만·엑셀≠손님 가격·중복 수, 뺄 이미지 수, **연결될 상품 예시(엑셀 상품명 ↔ 스토어 상품명·손님 가격·상태)**와 뺄 상품·가격 다른 상품 예시.
4. 결과를 보고 **[이대로 가져오기]**. 맞춰 보기를 안 했거나 스토어·이미지·검수 설정을 바꿨으면 가져오지 않습니다(다시 맞춰 보기). 맞춰 볼 때 받은 상품 목록을 30분 안에는 그대로 씁니다.
5. 잘못 가져왔으면 기록의 **[가져오기 되돌리기]**: 이 가져오기로 연결한 복사본과 새로 생긴 원본을 **이 프로그램에서만** 휴지통으로(네이버 상품은 그대로, 예전부터 있던 원본은 남기고 '가져옴' 표시만 지움). 파일을 고쳐 다시 가져오면 됩니다.

맞춘 결과:
- **스토어에 있는 상품** → **원본**(엑셀 내용, 상하단 빼고 브랜드·제조사·모델명·원산지는 '상세페이지 참조') + 그 스토어의 **판매 중 복사본**(지금 상품번호·관리코드·손님 가격·네이버 상태 그대로). 내리기·최신화·원본으로 되돌리기(내린 것)·다른 스토어로 복사가 보통 복사본과 똑같이 됩니다.
- 새로 생기는 원본의 **기준 가격 = 그 스토어의 지금 손님 가격**(엑셀 판매가가 아님 — 셀업·판매자센터에서 따로 건 할인까지 반영). 엑셀 판매가와 다른 상품은 **엑셀≠손님 가격** 목록으로 알려 줍니다.
- **원본 기준은 원본 엑셀과 같은 상품명(완전히 같음)**: 상품명이 같은 원본이 이미 있으면(예전에 원본 엑셀로 불러왔거나 다른 스토어에서 가져온 것) **그 원본에 연결**하고, 그 원본의 원본 이름·AI 키워드·상세·**기준 가격은 그대로** 둡니다('가져옴' 표시만, 고른 공통 이미지는 뺌 — 다른 스토어 손님 가격이 바뀌지 않게). 나중에 원본 엑셀에 같은 상품명이 있으면 '상품명 중복'으로 넣지 않습니다.
- **상품명 중복**: 한 스토어에 상품명이 완전히 같은 상품이 둘 이상이면(파일 안에서 같은 상품명이 또 나오거나, 그 원본이 이 스토어에 이미 다른 상품으로 관리 중) **앞 상품만 연결**하고 나머지는 '상품명 중복' 목록으로 알려 줍니다(네이버 상품은 그대로, 기록에서 CSV로 받기).
- **엑셀에는 있는데 스토어에서 지운 상품** → **버립니다**(원본으로 넣지 않음). 그 상품의 원본이 다른 경로로 이미 들어와 있으면 기록에 **[원본까지 삭제]** 버튼이 생깁니다 — 원본과 모든 스토어 복사본을 지웁니다(판매 이력·잠금은 남김).
- 같은 파일을 다시 넣었을 때 최신화로 판매자코드가 바뀐 상품은 '스토어에서 지움'이 아니라 **이미 연결**로 셉니다(예전 판매자코드로 1대1 확인).
- **스토어에는 있는데 엑셀에 없는 상품** → 가져오지 않고 **'스토어에만 있음'**으로 알려 줍니다. 아래 **가져온 기록**에서 숫자를 누르면 목록을 엑셀(CSV)로 받습니다(판매자코드·상품명·상품번호·네이버 상태·등록일). 이 프로그램이 이미 관리하는 복사본은 세지 않습니다.
- **스토어 상품과 1대1**: 판매자코드로 맞춘 스토어 상품 하나마다 복사본 하나. **대표 이미지 주소는 기준이 아닙니다**. 가져온 원본도 보통 원본과 똑같이 최신화·다른 스토어로 복사·원본으로 되돌리기가 됩니다(기준 가격 고정, 상하단 뺀 상세).
- 같은 파일을 다시 넣으면 이미 연결된 것은 '이미 연결'로 건너뜁니다.

구분과 가격:
- 가져온 원본은 **'가져옴 · 원본 이름 없음'** 표시가 붙습니다(올라가 있던 이름이 원본 이름 자리에 들어감). 출처 태그 `가져옴`, 스토어 이름도 붙고, 위 **가져온 원본 보기**로 그것만 봅니다. 복사본에는 **가져옴**, 이름 출처는 **'올라가 있던 이름'**.
- 가져온 복사본은 **가격 고정**: 최신화 직전에 네이버에서 **지금 손님 가격과 옵션 손님 가격을 다시 읽어 그대로** 올립니다(판매자센터에서 바꾼 가격도 지켜짐, %로 걸린 할인은 옵션 추가금에서도 빼서 손님 가격 그대로). **다른 스토어로 복사**할 때는 기준 가격(= 손님 가격)에 받는 스토어 템플릿을 적용합니다.
- **판매 이력**: 가져온 상품(그리고 이 프로그램이 올린 모든 판매 중 상품)은 판매 이력을 확인해야 **최신화·내리기**를 합니다(팔린 상품을 지우지 않게 — 그 전엔 '판매 이력 확인 전'으로 지우지 않고 멈춤, 복사본 화면 위에 안내).
  **[판매 이력 확인]**(가져온 기록·복사본 화면): ① 판매자센터에서 상품이 올라간 날 ~ 오늘 주문을 엑셀로 받아 **[판매 이력 파일 넣기]**(상품번호로 맞춰 팔린 상품 자동 잠금), ② 팔린 걸 아는 상품은 직접 **[잠금]**, ③ **[판매 이력 확인 완료]**(그 날부터 판매 이력을 아는 것으로). 그 뒤로는 최신화·내리기 때마다 **마지막 확인 뒤 주문만** 새로 받아 잠급니다.
  창에서 **[네이버에서 주문 받기]**로 그 기간을 커머스API로 받아도 됩니다(하루 단위 조회라 길면 오래 걸림). 가져오기가 끝나면 이미 받아 둔 주문도 가져온 복사본과 다시 맞춥니다.
- '가져온 원본을 검수 완료로 표시'(기본 켬): 이미 올려 둔 상품이라 검수 완료로 넣습니다. 끄면 미검수로 들어가 눈검수 대상이 됩니다.
- 최신화는 보통 복사본처럼 **지우고 새로 올리므로** 상품번호·관리코드가 바뀝니다.
- 스토어마다 **API 키**가 있어야 목록을 받습니다(스토어 화면에서 넣기).

## 생활화학·살생물제 (productCertificationInfos 오류)

네이버는 생활화학제품·살생물제 **인증 대상 카테고리**에 신고·승인번호 없이 올리면 `productCertificationInfos` 오류로 막습니다. 공구·커튼처럼 화학제품이 아닌 **물건**이 그 카테고리에 있는 경우가 많습니다.

- **판정**: 카테고리가 인증 대상인지 네이버에서 확인(한 번 확인한 카테고리는 기억) → 대상이면 상품명·옵션으로 **물건 / 화학제품 / 애매**를 나눕니다. 규칙으로 못 정하는 것은 AI(설정의 AI 키)가 정합니다.
  - **물건** → 카테고리 그대로 **'인증 대상 아님'**(chemicalCertifiedProductExclusionYn)으로 올립니다.
  - **화학제품·애매** → **생활화학 보류**. 올리지 않습니다(등록·최신화·다시 올리기 모두). 사람이 검수해 **물건으로** 바꾸거나, 카테고리를 바꾸거나, 지웁니다.
- 어디서: 상세 정리 ⑦, 원본 상품의 **생활화학 판정**(거르기 '생활화학 보류'), 복사본 화면의 생활화학 실패 줄의 **생활화학 판정** 버튼. 판정이 물건으로 바뀌면 그 이유로 실패했던 복사본은 다시 등록 대기로 갑니다.
- **원본·복사본 모두 삭제**(원본 상품에서 고른 뒤): 원본과 모든 스토어 복사본을 지웁니다. 네이버에 안 올라간 것은 바로 휴지통, **다른 스토어에서 판매 중인 복사본은 네이버에서 내린 뒤** 원본도 휴지통으로(지금 처리 중인 복사본은 끝난 뒤 이어서 내림). **잠긴 복사본**(판매 이력·직접 잠금 — 판매 중·내림·대기 상관없이)은 그 줄과 원본만 남기고, 잠기지 않은 복사본은 내리거나 휴지통으로 보냅니다.
- **주의**: 진짜 화학제품(세제·방향제·살충제·코팅제·접착제·양초 등)을 인증이 필요 없는 다른 카테고리로 옮겨 올리면 네이버 카테고리 회피 제재와 화학제품안전법 위반 위험이 있습니다.

## 기준 가격 (기준 가격 = 판매가 - 할인가)

**기준은 늘 손님이 내는 금액 하나**입니다. 원본 엑셀의 **할인가(S열)는 할인 금액**이고, 프로그램은 **기준 가격 = 판매가(R열) - 할인가(S열)**, 즉 실제로 팔 금액만 씁니다. 원가(U열)·추가판매가(T열)는 쓰지 않습니다.
할인(표시 할인율)은 **네이버에 올릴 때만** 붙입니다.
**기준 가격은 고정**: 처음 원본 파일을 넣을 때(기존 상품 가져오기로 새로 생긴 원본은 그 스토어의 손님 가격) 정해지고, 원본 엑셀을 다시 올려도·가져오기를 해도 바뀌지 않습니다.
스토어 가격(손님이 내는 값) = **기준 가격 × (1 + 스토어 가격 차이 %)**, 100원 올림. 스토어 가격 차이 %를 바꾸면 다음 등록·최신화 때 그 스토어 가격 차이 %로 다시 계산됩니다. (예전 '흔들기'는 없앴습니다 — 스토어마다 다르게 하려면 스토어 가격 차이 %를 다르게.) 엑셀 할인가로 즉시할인을 따로 걸지 않습니다.
**기준 가격 수정**(역마진 등 — 이때만 고친 가격이 새 기준): 원본 상세 창의 '기준 가격' **[수정]**, 또는 원본 상품 화면 위 **[기준 가격 수정]**에서 양식 엑셀을 받아 채워 올립니다. 엑셀은 한 줄마다 **원본 상품명 / 복사본 상품명(AI로 만든 이름도) / 판매자 관리코드 / 상품번호** 중 하나만 채우면 원본을 찾고(상품명은 완전히 같을 때만), 먼저 미리보기(찾음·못 찾음·여러 개에 맞음)를 보여 준 뒤 바꿉니다.
바꾸면: 아직 안 올린 복사본은 가격을 바로 다시 계산, **판매 중 복사본은 네이버 가격만 바로 바꿈**(상품을 지우지 않음 → 리뷰·판매 기록 그대로, 실패하면 다음 최신화 때 새 가격으로), 가져온(가격 고정) 복사본은 손님 가격 = 새 기준 가격. 바꾼 기록은 원본마다 남습니다.

## 원본 상세·옵션 고치기

원본 엑셀을 다시 올려도 원본을 덮어쓰지 않으므로, 원본 내용은 **원본 상세 창 → 상세·옵션 [상세·옵션 고치기]**에서 고칩니다.
- **상세페이지**: HTML을 직접 고치고 바로 미리보기.
- **옵션**(조합형): 옵션 이름 1~3, 값, 추가금(기준 가격에 더하는 금액), 판매(사용) 여부를 고치고 더하기·빼기. 모두 빼면 옵션 없는 상품. 같은 옵션 두 번·빈 값·옵션 이름 빠짐은 막고, 추가금이 네이버 허용 범위를 벗어나면 알려 줍니다. 단독형·직접입력형 옵션은 고칠 수 없습니다.
- 상품명(원본 기준)과 기준 가격([기준 가격 수정])는 여기서 바꾸지 않습니다.
- 아직 안 올린 복사본은 올릴 때 새 내용으로, **판매 중 복사본은 네이버에 바로 보내지 않고 다음 최신화·다시 올리기 때** 반영됩니다. 이 원본의 복사본이 등록 중이면 끝난 뒤에 고칩니다.
- 고치기 전 내용을 남겨 두어 **[마지막 수정 되돌리기]**로 돌릴 수 있고, 고친 기록(메모 포함)이 창과 실행 기록에 남습니다.
**표시 할인율**(기본 30%, 스토어 템플릿에서 스토어별로, 0이면 할인 없음): **손님 가격은 1원도 바꾸지 않고**, 네이버 판매가 = 손님 가격 ÷ (1 - 30%)를 100원 단위로 올린 값, 그 차이를 **금액으로** 즉시할인합니다. 할인율은 그 %에 아주 가깝게(예: 70,200원 → 판매가 100,300원, 할인 30,100원(30.01%) → 손님 70,200원 그대로). 복사본 상세에 네이버 판매가·즉시할인·실제 할인율·손님 가격이 나옵니다.
(예전 버전은 할인율을 정확히 맞추느라 손님 가격이 최대 수백 원(%에 따라 수천 원) 올라갔습니다. 그렇게 올라간 상품은 다음 최신화 때 맞춰집니다.)
가격은 **올리는 순간의 기준**으로 다시 정합니다(처음 등록·최신화·다시 올리기 모두 같게). 템플릿·설정 기본값을 바꾸거나 기준 가격을 고치면 아직 안 올린 복사본 가격도 바로 다시 정합니다. 목록 가격 칸은 **손님 가격**(크게)과 **네이버 판매가 · 표시 할인율**(작게)을 보여 주고, 예전 규칙으로 올라간 상품은 '예전 규칙'으로 표시합니다.
**가격 칸 확인**: 원본 엑셀 불러오기·상세 정리 엑셀 올리기 때 가격 칸이 규칙과 다르게 적힌 줄이 있으면 **넣기 전에 경고 창**이 뜹니다 — 할인가가 판매가의 절반 넘음('할인된 가격'을 적은 것 같음), 할인가가 100원 미만(퍼센트를 적은 것 같음), 할인가가 판매가 이상, 원가가 손님 가격보다 큼. 줄 번호·예시·이대로 넣으면 될 손님 가격을 보여 주고 **넣지 않기** / **그래도 넣기**(손님 가격 = 판매가 - 할인가)를 고릅니다.
**재고**: 등록할 때 상품·옵션 모두 늘 **1,000개**(설정 → 가격의 '등록 재고', 0이면 엑셀 재고수).
(예전 버전은 할인가를 '할인된 가격'으로 잘못 읽었습니다. 이 버전을 처음 켜면 기준 가격과 아직 안 올린 복사본 가격을 한 번 다시 계산합니다.)

**원본 일괄 수정**: 원본 상품에서 고른 뒤 **일괄 수정** → 판매자코드 비우기, 재고수(상품·옵션 모두). 원본 엑셀을 다시 불러오면 파일 값으로 돌아가지만, 등록 재고는 설정의 '등록 재고'(기본 1,000개)가 늘 우선합니다. 네이버에 넣는 판매자 관리코드는 프로그램이 스토어마다 만듭니다(`스토어코드-원본번호-회차`).

## 창의 2차 확인

모든 창에서 확인·저장·실행 버튼(삭제·복사·넣기·바꾸기 등)을 누르면 바로 실행하지 않고, 같은 창 안에 **"한 번 더 확인하세요"** 화면이 나옵니다 — 어느 창에서 어떤 버튼을 눌렀는지, 그 창의 설명(어떻게 되는지), 지금 고른 설정을 보여 주고 **[확인 — 실행]**을 눌러야 실행합니다. **[← 돌아가기]**로 돌아가 고칠 수 있습니다. 취소·닫기·넣지 않기는 바로 됩니다.

- 2차 확인 화면에는 꺼 둔 체크(✘)도 보이고, 그 창에 나온 말 중 **용어 설명**(기준 가격·잠금·최신화 등)을 함께 보여 줍니다. 고를 것을 안 골랐으면 2차 확인 전에 바로 알려 줍니다.
- 창이 아닌 버튼으로 바로 실행되던 위험·비용 동작도 같은 확인 창을 거칩니다: 시작·1건만 시험, 이 건만 지금 처리, 생활화학 판정(AI 비용), 원본으로 되돌리기, 대기·실패 취소, 등록 중단, 상세 정리의 공통 이미지·전화번호 지우기·보류 판정, 대기 중인 복사본 가격 다시 계산, AI 키워드 차단, 검수 완료 풀기 등. 브라우저 기본 확인창은 쓰지 않습니다(스토어 템플릿 이미지 지우기만 창 안에서 한 번 묻습니다).
- 원본 엑셀 '올리기 전 확인' 창을 ✕·Esc로 닫으면 넣지 않은 것으로 하고 잡아 둔 파일을 지웁니다.

## 용어 설명

왼쪽 메뉴 **용어 설명**에 프로그램에 나오는 말(원본·복사본·기준 가격·손님 가격·스토어 가격 차이 %·표시 할인율·가격 고정·회차·최신화·잠금·판매 이력 확인·상품명 중복·대표 이미지 겹침·검수·올릴 준비·생활화학 보류·휴지통 등)의 뜻을 모아 두었습니다(찾기 가능).
- 화면의 제목·칸 이름 옆 **ⓘ**에 마우스를 올리면 뜻이 보이고, 누르면 설명 창(→ 용어 설명 전체 보기)이 뜹니다.
- 화면마다 맨 위에 **한 줄 안내**(이 화면에서 무엇을 하는지)가 있습니다.
- 가격 용어는 이 네 가지로만 구분합니다: **기준 가격**(원본에 저장된 손님 가격, 모든 스토어의 출발점 — 예전 '기준 구매가'·'원본가'), **스토어 가격 차이 %**(그 스토어만 기준 가격에서 더하거나 빼는 %, 마진이 아님 — 예전 '가격 조정 %'·'마진율'), **손님 가격**(손님이 실제로 내는 금액 = 기준 가격 × (1 + 스토어 가격 차이 %)), **네이버 판매가·즉시할인**(표시 할인율로 자동 계산).

## 삭제와 휴지통

원본 상품·복사본 목록에서 고른 뒤 **삭제** → 확인 창에서 **[삭제합니다]**를 누르면 **휴지통**으로 옮깁니다(바로 없어지지 않음).
- **복사본 화면·눈검수의 삭제는 기본이 '원본까지 같이 삭제'**입니다: 고른 복사본의 원본과 그 원본의 **모든 스토어 복사본**을 지웁니다. 네이버에 안 올라간 것은 바로 휴지통, **판매 중인 복사본은 네이버에서 내린 뒤** 원본도 휴지통(판매 이력·잠금이 있는 원본은 남김). 등록이 도는 중이면 내리기는 대기에 넣습니다(끝난 뒤 시작에서 '내리기'). 확인 창에서 체크를 끄면 고른 복사본만 휴지통으로 옮깁니다(예전 방식).
- 원본을 지우면 그 원본의 복사본(아직 안 올린 것·내린 것)·이름 후보·AI 키워드도 함께 옮깁니다.
- 복사본을 지우면 붙어 있던 상품명은 원본의 안 쓴 후보로 돌아갑니다.
- **네이버에 올라가 있거나 처리 중인 것은 지우지 않습니다**(먼저 '내리기'). 몇 개 뺐는지 알려 줍니다.
- **네이버 상품은 그대로 두고 이 프로그램에서만 빼기**: 삭제 확인 창(원본 삭제·원본·복사본 모두 삭제·복사본 삭제)에서 켜면, 판매 중인 복사본이 있어도 **네이버에서 내리지 않고** 이 프로그램에서만 휴지통으로 옮깁니다(잘못 가져온 상품을 빼고 다시 가져올 때 등). 휴지통에 '판매 중 — 네이버에 그대로'로 남고 되살릴 수 있습니다. 이렇게 뺀 판매 중 상품은 스토어·상품번호·판매자코드·직접 잠금을 기억해 두었다가, 기존 상품 가져오기로 다시 넣으면 직접 잠금을 되살리고 예전 판매자코드로도 찾습니다. 지금 처리 중인 것만 뺍니다.
- 휴지통에는 지울 때의 기록(스토어, 관리코드, 회차, 상태, 올린 날, 가격, 지난 회차)이 그대로 남고 **자세히**로 볼 수 있습니다.
- **휴지통** 메뉴에서 되살리기(원래 자리로), 완전히 삭제, 휴지통 비우기. 되살릴 때 **상품명이 완전히 같은 원본**이 그새 들어왔거나(예전 버전의 이미지 기준으로 지운 원본 포함) 그 스토어에 같은 원본의 복사본(내림 포함)이 있으면 그 항목은 건너뛰고 이유를 알려 줍니다. 번호가 그새 다른 원본·이름에 쓰였으면 새 번호로 되살리고, 없어진 복사 계획은 비우며, 항목마다 따로 처리해 하나가 막혀도 나머지는 되살립니다.

## 원본과 복사본

불러온 엑셀 한 줄이 **원본**이고, 다른 스토어로 올리는 것은 원본에서 만든 **복사본**입니다(원본당 최대 2곳 — **내림도 그 스토어 자리를 차지**해 셉니다. 자리를 비우려면 복사본을 휴지통으로 삭제).
**복사본 → 원본으로 되돌리기**(복사본 화면에서 고른 뒤): 아직 안 올린 복사본(대기·실패)과 **내린** 복사본을 그 스토어에서 없앱니다(휴지통에 기록). 원본은 그대로 남아 복사 자리가 비고, 붙어 있던 상품명은 원본의 후보로 돌아갑니다. 네이버에 올라가 있거나 처리 중인 것·판매 이력(잠금)이 있는 것은 뺍니다.
**다른 스토어로 보내기**(복사본 화면에서 고른 뒤): 같은 조건(안 올린 것·내린 것)의 복사본을 다른 스토어로 옮깁니다 — 지금 스토어에서는 사라집니다. 받는 스토어의 **남은 자리만큼만**, 그 스토어에 같은 원본이 이미 있으면(내린 것 포함) 빼고 옮깁니다. 상품명(A·B)은 그대로, 가격은 받는 스토어 템플릿 기준으로 다시, 1회차 새 등록 대기가 됩니다(내린 복사본은 받는 스토어에 새로 만들고 원래 것의 지난 회차 기록은 휴지통으로). 예: 온누리로 복사해 둔 것을 레드꼬꼬 남은 자리 채우기.
**AI 이름 A·B**: 원본마다 AI 키워드로 이름 A·B를 만듭니다(B는 앞 3단어만 두고 섞어 양식이 조금 다름). **복사할 때는 늘 A부터** 붙고(A를 쓴 복사본을 되돌리면 다음 복사에 다시 A), 화면의 A·B 글자는 그 이름의 양식 그대로입니다.
**원본 상품** 화면에서 원본 바로 아래 줄에 복사본이 보입니다: 스토어 코드·이름, 복사한 상품명, 가격(원본 대비 %), 관리코드·회차, 올린 날, 판매 수, 상태. 줄을 누르면 상세(같은 원본의 다른 복사본, 지난 회차, 판매 이력)가 열립니다. 복사본 전체는 **복사본** 화면에서 스토어·상태·올린 날로 거릅니다.


- **판매자 관리코드**를 프로그램이 스토어마다 만들어 등록합니다: `스토어코드-원본번호-회차` (예: `S07-0012345-2` = 스토어 S07, 원본 #12345, 2번째 등록). 스마트스토어센터에서 이 코드로 검색하면 어느 원본의 몇 번째 등록인지 바로 압니다. 형식은 설정에서 바꿀 수 있습니다.
- **원본 상품** 화면의 '스토어 칸'에 원본마다 2칸(설정의 최대 수)이 있고, 들어간 스토어 코드가 상태 색으로 표시됩니다(판매 중 초록, 대기 회색, 실패 빨강, 최신화 대기 파랑, 내리기 대기 주황). 빈 칸은 점선입니다. 위의 칸으로 '미복사 / 1회 / 2회 복사'를 거릅니다.
- **복사본** 화면의 각 줄에는 같은 원본이 있는 다른 스토어로 가는 버튼이 있고, 줄을 누르면 원본과의 비교, 다른 스토어 등록, 지난 회차가 보입니다.
- 원본·복사본 줄마다 **바로 가기** 칸이 같은 자리에 있습니다: **새 상품 ↗**(네이버에 올라간 그 상품, 복사본만) · **원본 ↗**(엑셀 수집URL) · **원본 정보**(복사본만). 상품 이미지에 마우스를 올리면 크게 보입니다.
- 원본 줄의 표시: **경고**(금지 키워드·상표 단어) / **반복**(같은 단어 3번 이상) / 동영상.
- **복사본 · 스토어 고르기**: 사업자별 카드에 **상품명 변경 필요**(빨강) · **올릴 준비 됨**(파랑) · **판매 중**(초록)을 크게, 최신화·내리기 대기·실패·남은 자리·마지막 작업 때를 작게 보여 줍니다. 지금 처리 중인 스토어는 파란 테두리와 진행 수가 붙습니다. 복사본 화면 위 칸에 **상품명 변경 필요 / 상품명 변경 완료**가 있습니다.

## 최신화와 내리기 (잠긴 상품은 지우지 않음)

- **잠금**이 걸린 복사본은 최신화·내리기에서 항상 빠집니다. 예약할 때 한 번 거르고, 실행 직전에 그 스토어의 주문을 다시 가져와 한 번 더 확인합니다. 주문을 가져오지 못하면 그 스토어에서는 아무것도 지우지 않습니다.
- 잠금은 두 가지입니다.
  - **자동 잠금 (판매 이력)**: 취소·반품을 뺀 실제 판매(결제 완료·배송·구매확정·교환)가 1건이라도 있으면 잠깁니다. 취소·반품만 있는 복사본은 잠그지 않아 지울 수 있습니다. 아직 '결제 완료'인 주문도 판매로 보고 잠그며, 나중에 취소가 확정되면 다음 주문 가져오기 때 풀립니다.
    설정에서 끌 수 있고, "취소·반품만 있어도 잠금"을 켜면 이력이 조금이라도 있으면 모두 잠급니다.
  - **직접 잠금**: 판매 이력과 상관없이 복사본 화면에서 골라 **잠금** / **잠금 풀기**, 또는 상세에서 **직접 잠금**. '잠금 풀기'는 직접 건 잠금만 풉니다(판매 이력 잠금은 그대로).
- 복사본 화면의 **잠금** 칸으로 잠긴 것만 볼 수 있고, 줄마다 잠금 이유(판매 이력 n개 / 직접 잠금)가 보입니다.
- 판매 이력은 두 곳에서 받습니다.
  - **판매자센터 주문 (판매 현황 화면)**: 스토어마다 커머스API로 판매자센터의 주문을 가져옵니다. 결제뿐 아니라 배송·취소·반품·구매확정 등 상태가 바뀐 주문을 모두 받아 상태를 최신으로 유지합니다. 처음엔 최근 30일, 다음부터는 마지막으로 가져온 때부터 이어서(10분 겹쳐서) 받습니다.
    - **자동 가져오기**: 기본은 **꺼짐**(주문은 다른 프로그램으로 봄). **최신화·다시 올리기·내리기**를 할 때는 그 스토어 주문을 늘 먼저 가져와 판매된 상품은 지우지 않게 합니다(그 스토어 첫 확인은 최근 7일, 그 뒤엔 마지막 확인부터). 필요하면 설정에서 간격(분)을 넣어 켭니다. 스토어 여러 곳(최대 8곳)을 동시에 가져오고, 오른쪽 아래 알림에서 **중단**하면 바로 멈추고 자동 가져오기도 꺼집니다(설정에서 다시 켬). 네이버 API는 스토어(애플리케이션)마다 시간당 요청 한도가 있어 넘으면 `429 GW.QUOTA_LIMIT`가 뜹니다 — 1시간쯤 뒤 다시 하세요.
    - **기간 지정해서 가져오기**: 시작일~종료일을 골라 지난 주문을 다시 받습니다(네이버가 하루 단위로만 조회해 주므로 날짜 수만큼 나눠 조회).
    - **판매 현황** 화면에서 기간·스토어·맞춤 여부로 거르고, 주문 수·수량·판매된 복사본/원본·취소·반품·못 맞춘 주문과 스토어별 합계를 봅니다. 주문을 누르면 그 복사본 상세가 열립니다.
    - 취소·반품된 주문도 판매 이력으로 셉니다(지우지 않는 쪽이 안전하므로).
  - **판매 이력 파일 가져오기**: 아바닛 같은 주문 수집 웹에서 내려받은 주문 엑셀/CSV. `판매자관리코드`(이 프로그램이 붙인 코드), `상품번호`, `원상품번호`, `상품명` 중 있는 열로 복사본을 찾고, `주문번호`·`수량`·`판매처`·`결제일` 열이 있으면 함께 씁니다. 화면 어디에나 끌어다 놓고 '판매 이력으로'를 골라도 됩니다.
- 주문은 지금 회차와 지난 회차의 상품번호 모두로 맞춥니다.

- **최신화**: 판매 중인 건을 네이버에서 지우고 같은 내용(같은 이름·가격, 설정으로 새 이름)으로 다시 올립니다. 회차가 1 오르고 판매자 관리코드 끝 숫자가 바뀝니다. 지운 회차는 '지난 회차'에 남습니다.
- **최신화·다시 올리기·내리기 전 안전장치** (다시 올리기도 최신화와 똑같이):
  - **판매 이력 확인 (모든 판매 중 상품)**: 그 상품이 올라간 날부터 그 스토어 판매 이력을 알고 있어야 지웁니다 — 가져온 상품뿐 아니라 이 프로그램이 올린 상품도. 처음 주문을 받는 스토어는 최근 며칠치만 알기 때문에 복사본 화면 위 **[판매 이력 확인]**(판매자센터 주문 파일·직접 잠금 → 확인 완료, 또는 네이버에서 주문 받기)을 먼저 하세요. 지우기 직전에는 마지막 주문 확인이 5분 넘게 지났으면 그 스토어 주문을 다시 받아 실행 중에 팔린 상품도 잠급니다.
  - **올릴 내용을 모두 준비한 뒤에 지움**: 이미지·스토어 상단·하단·옵션 그림·등록 내용을 다 만든 다음에 지우고, 지운 뒤에는 등록만 합니다(실패하면 몇 번 다시 시도). 그래도 실패하면 메시지에 **'네이버에서 지워짐 — 다시 등록 필요'**로 남습니다(실패 재시도로 다시 올림).
  - 이름이 없는(상품명 변경 필요) 복사본은 지우지 않습니다. 지금 등록 중인 복사본은 이름 바꾸기·기존 상품 가져오기에서 빠집니다(네이버에 예전 이름이 올라가는 일 없게).
  - **네이버 상태 확인**: 그 스토어 상품 목록을 받아 복사본마다 네이버 상태를 적습니다(스토어처럼 **판매 중·품절·판매중지·판매금지·승인 대기·스토어에 없음**, 전시중지도 표시). **판매중지·판매금지·스토어에 없음** 등은 최신화하지 않고 '네이버 ○○ 상태라 최신화하지 않음'으로 남깁니다(지우고 다시 올리면 다시 판매되므로). 품절은 최신화합니다(재고 1,000으로). 복사본 화면 **[네이버 상태 확인]**으로 언제든 확인하고, **판매중지·판매금지 등** 칸으로 그것만 봅니다.
  - **지우기 전에 다시 올릴 수 있는지 먼저 확인**: 카테고리·필수 값·옵션 손님 가격을 먼저 확인하고, 막히면 **지우지 않고** 실패로 남깁니다(예전엔 지운 뒤에 막혀 상품이 사라질 수 있었음).
  - 지운 뒤 등록이 실패한 가격 고정 복사본은 가격을 다시 계산하지 않습니다(템플릿·설정을 바꿔도 손님 가격 그대로).
- **내리기**: 네이버에서 지웁니다. 원본의 칸이 비어 다른 스토어(또는 같은 스토어)에 다시 계획할 수 있고, 스토어 자리도 돌아옵니다.
- **스토어별 최신화**: 스토어 화면에서 스토어마다 **최신화**를 누르면 "올린 지 7·30·60·90일 넘은 것 / 판매 중 전체" 중 고른 대상(잠금 제외)이 몇 건인지 보여 주고, **바로 하기**(그 건들만 지금 처리) 또는 **대기에 넣기**를 고릅니다.
- 쓰는 법(여러 스토어를 한꺼번에): 복사본 화면에서 **올린 날**(7·30·60·90일 넘음)과 **판매 중**으로 거르고, 고르거나 '조건에 맞는 전체 고르기' → **최신화** / **다시 올리기** / **내리기** → **바로 하기**(고른 것만 지금, 다른 대기 건은 그대로) 또는 **대기에 넣기**(나중에 시작 칸에서 종류를 골라 처리). 대기는 **대기·실패 취소**로 되돌릴 수 있습니다. 예전에 네이버에 올렸던 줄(지운 뒤 실패·내린 것 다시 올리기·회차 초기화)이나 잠긴 줄은 취소해도 **지우지 않고 '내림'**으로 둡니다. 내리기 대기를 취소하면 '원본까지 삭제' 예약도 풀립니다.
- **다시 올리기**(최신화와 따로): 문제가 있는 상품을 지우고 **같은 상품명·지금 가격**으로 다시 올립니다. 판매 중인 건은 네이버에서 지운 뒤(이미 스토어에서 지운 상품이어도 됨) 다시, **내림** 상태 건은 지우는 단계 없이 다시 올립니다(직접 고르거나 '내림'으로 거른 때만, 남은 자리만큼). 회차가 1 오르고 지난 회차 기록에 '다시 올리기'로 남습니다. **최신화**는 오래된 판매 중 상품용(설정에 따라 새 상품명)이고 내린 건에는 걸리지 않습니다.
- 스토어 화면과 한눈에 보기에서 스토어마다 판매 중·대기·실패·내림 수와 가장 오래된 등록이 며칠 전인지 보입니다.
- **엑셀(CSV) 받기**: 복사본 화면 고르기 줄의 **[⬇ 엑셀(CSV) 받기 — 고른 n건]**(고른 것이 없으면 '지금 보이는 조건 N건'). 관리코드, 회차, 올린 날, 원본 번호 등이 들어갑니다.

## 상품명: AI 키워드(keep · 다른 이름 · 맥락) 조립 (기본 방식)

**현황은 늘 오른쪽 아래에**: 도는 작업은 진행률, 끝난 작업은 1분 동안 결과(오류는 10분, ✕로 닫음). AI 키워드 **일괄 처리 중**이면 원본 수·보낸 지 얼마·마지막 확인 때가 계속 보이고(지금 확인·중지), **실패한 원본**은 사유와 함께 빨간 카드로 남아 **다시 받기**로 그 원본만 다시 받습니다. 끝나면 받은 수·실제 비용이 보이고 이름은 복사본에 자동으로 붙습니다.
**상품명 바꾸기 → AI 키워드**: 키워드가 없는 원본은 비용 안내 뒤 먼저 받습니다. 받기 창에서 처음 골라져 있는 방식은 **설정 → AI 키워드 → 키워드 받기 기본 방식**(기본 **즉시**, 1~2분)이고, 즉시면 다 받은 뒤 바로 이름을 붙이고 일괄이면 끝나는 대로 자동으로 붙습니다 — 키워드를 기다리던 복사본은 **누른 그대로**(이미 이름이 있던 것·내린 것도 새 이름으로, '이미 이름이 붙은 복사본도' 끄면 이름 없는 것만) 바뀝니다. 기다리는 동안 셔플·AI로 짓기·직접 고치기로 이름을 바꾸면 그 복사본은 키워드가 와도 덮어쓰지 않습니다. 결과 확인은 프로그램이 켜져 있을 때 1분마다(껐다 켜도 이어서) 하고, 바뀐 수는 작업 기록에 남습니다. **이미 이름이 붙은 복사본도 새 이름으로**(기본 켬)를 두면 누를 때마다 새 이름이 됩니다 — 후보 A·B를 다 쓰면 같은 키워드로 다른 조합을 더 만들고(AI는 다시 안 부름), 한 번 바꿔 버린 이름은 다시 돌아오지 않습니다. 끄면 '상품명 변경 필요'인 것만 붙입니다. 원본 엑셀을 다시 불러와 원본 상품명이 바뀌면 그 원본의 AI 키워드와, 아직 안 올린 복사본의 이름이 무효가 되어 다시 받습니다.

AI는 원본마다 한 번 세 묶음만 줍니다. 상품명은 프로그램이 조립합니다(`uploader/ctxname.py` → `make_names_v2`).
- **keep**(최대 6): 원본 상품명에 있는 핵심 검색 단어, 중요한 순. 원본에 그대로 있는 것만 씀.
- **다른 이름 core**: 같은 물건을 부르는 통용 명칭·동의어·줄임말·표기 차이·상위 명칭(원터치텐트 → 텐트, 그늘막 → 차양막). **용도·조합 core2**: 용도형 명칭과 조합용 목적 표현(차박텐트, 거치, 수납). 둘 합쳐 최대 8개, 최소 없음. 없는 재질·구조·기능·규격, 더 좁은 하위 종류, 다른 판매 품목은 금지. 이름에는 core 전부 + core2 앞 2개를 맥락 앞에, 나머지 core2는 남은 원본 단어 뒤에 넣습니다(A는 1번째부터, B는 2번째부터 순서만 바꿈). 금지어 → AI 다른 이름 확인에서 core·core2·맥락을 단어별로 보고 차단할 수 있습니다.
- **지시(프롬프트)가 바뀌어도 자동으로 다시 받지 않습니다.** 원본 상품 화면 AI 이름 칸 → '예전 지시로 받은 키워드'로 골라 AI 키워드 받기를 누르면 비용 안내에서 '새 지시로 함께 다시 받기'를 고를 수 있습니다. 다시 받으면 그 원본의 안 쓴 AI 이름과 안 올린 복사본의 AI 이름을 새로 만들어 붙입니다(올린 것은 그대로).
- 지시문은 요청마다 같아서 **프롬프트 캐시**를 씁니다: 지시문 부분은 처음 한 번 기억시키고(즉시 5분 기억 1.25배, 일괄 1시간 기억 2배) 그 뒤 요청은 0.1배. 다시 쓸 때마다 기억 시간이 새로 시작됩니다. 즉시 모드는 첫 요청 1개를 먼저 끝낸 뒤 나머지를 한꺼번에 보내 캐시를 맞춥니다. 일괄 50% 할인과 함께 적용되며, 실행 기록에 **캐시로 읽은 토큰**과 캐시 요금을 반영한 실제 비용이 나옵니다.
- **맥락 ctx**(최대 8): 쓰는 장소·사람·용도·상황.

이름 = **[원본 앞 4단어] + keep + 다른 이름(core) 전부 + 용도·조합(core2) 2개 + 맥락 + 남은 원본 단어 + 나머지 core2 + 숫자·수량·연식**, 최대 50자(공백 포함).
- 앞 4단어를 셀 때 **숫자·수량·연식만 있는 단어**(1+1, 2024형, 10개, 3P, 5개입, 2025년식 …)는 빼고 맨 뒤로 보냅니다(자리가 없으면 빠짐). 크기(30cm)는 그대로.
- 자리가 모자라면 넣는 순서: keep → 다른 이름 → 맥락 2개 → 남은 원본 단어 → 맥락 2개 더 → 숫자. 무작위 없이 정해진 순서라 같은 입력이면 같은 이름.
- 원본마다 이름 **A·B**를 한 번에 만들어 1번째·2번째 복사본에 붙입니다. **A·B가 달라 보이게**: 보라(core·core2)는 자기 몫(가장 확실한 1개는 둘 다, 나머지는 번갈아)을 먼저 넣고 자리가 남으면 상대 몫도 빌려 써서 최대한 채우고, 맥락은 반씩 나눠 씁니다. A는 원본 앞 4단어 → keep → 보라 → 맥락 → 남은 원본 단어 순서, **B는 원본 앞 3단어만 두고 나머지를 섞되 바로 뒤 4자리에 A 앞쪽에 없는 단어(주로 AI 단어)가 오게** 고릅니다(숫자·수량·연식은 늘 맨 뒤). 3번째 스토어부터는 A·B 방식을 번갈아 다른 조합으로. 33개 스토어 전체 중복·상표·원본과 같은 이름이면 다른 조합으로 최대 10번, 안 되면 '상품명 변경 필요'.
- **A·B 확인**: 원본 상품 화면에서 원본 이름 아래에 A·B 이름과 어디에 쓰였는지(예: `S01 판매 중`, `S02 올릴 준비`, `남음`)가 보입니다. 원본을 누르면 **상품명 후보** 탭에 'AI 이름 A/B'로, 복사본 화면 태그에도 'AI 이름 A/B'로 나옵니다. 위쪽 **AI 이름** 칸에서 '안 쓴 AI 이름 남음'·'다 씀'·'키워드 안 받음/받는 중/실패'로 걸러 볼 수 있습니다. 남은 이름은 이 원본을 다른 스토어에 복사할 때 바로 붙습니다.
- **상품명 다시 바꾸기**(이미 AI 이름이 붙은 복사본)는 안 쓴 B를 가져가지 않고 **새 조합**을 만들어 붙입니다 — B는 다음 스토어 몫으로 남습니다. 글자는 **A = 1번째 복사본에 붙은 이름, B = 2번째 복사본(없으면 안 쓴 이름)** 순서라, 다시 바꿔도 그 복사본 이름은 계속 A입니다. 바꿔 버린 이름은 안 보이고 '바꿔서 안 쓰는 이름 n개'로만 표시됩니다.
- **내린 복사본(내림)도 상품명을 바꿀 수 있습니다** — 네이버에 없으니 바꿔도 안전하고, '다시 올리기'를 하면 바꾼 이름으로 올라갑니다. 이미 올라가 있는(판매 중) 복사본만 건너뜁니다.
- **복사본 삭제 때 원본도 같이**: 삭제 창의 '원본 상품도 같이 휴지통으로'를 체크하면 고른 복사본의 원본도 휴지통으로 갑니다(그 원본의 이름 후보·AI 키워드·다른 스토어 복사본도 함께 — 창에 몇 개인지 나옴). 다른 스토어에 올라가 있거나 처리 중인 원본은 남깁니다. 휴지통에서 되살릴 수 있습니다.
- **회차 초기화**(복사본 화면 버튼): 지난 회차 기록을 지우고 1회차로. 고른 복사본 / 이 스토어 전체 / 모든 스토어 전체. 아직 안 올린 건은 바로 1회차, 판매 중·내린 건은 지금 상태 그대로 두고 최신화·다시 올리기로 다시 올릴 때 +1 하지 않고 1회차(관리코드 끝 -1)로 올라갑니다. 네이버 상품은 건드리지 않습니다.
- 복사본 화면의 **올릴 준비** 칸(스토어 카드의 '올릴 준비 됨')은 **상품명을 바꿨고 + 검수 완료**이면서 아직 네이버에 안 올린 등록 대기 복사본만 셉니다. 복사본 화면 위 칸은 창을 내리지 않아도 상품이 보이게 **한 줄**로 작게 나옵니다(칸에 마우스를 올리면 설명). 올린 것은 '판매 중', 실패한 것은 '실패' 칸에 있습니다.
- 다른 이름·맥락 단어마다 금지어·막연한 말·**상표 단어**·직접 차단한 단어를 뺍니다.
- **같은 단어 3번 이상 금지**(설정 `max_word_repeat`, 예: 커튼·린넨커튼·가리개커튼, 보물탐지·탐지기·금속탐지): 띄어쓰기와 관계없이 붙여 쓴 단어 속까지 셉니다(사전 없이 — 다른 단어의 앞부분이거나, 앞에 2자 이상이 붙은 뒷부분이면 단어로 봄. 화이트·헤드라이트의 '이트'처럼 소리만 겹친 건 반복 아님). 단어 뒤에 한 글자만 더 붙은 말은 다른 단어로 셉니다(탐지기·받침대·서랍장 ≠ 탐지·받침·서랍 — 금속탐지기는 금속+탐지기). 단 -용·형·식은 같은 단어(캠핑용 = 캠핑). 단어를 넣을 때마다 검사해 반복을 만드는 단어는 넣지 않습니다(원본 앞 4단어에서 이미 반복이면 그 단어를 빼고 다음 원본 단어로). 셔플·직접 입력도 같은 기준이고, 반복이 남은 이름은 복사본 목록에 '반복' 표시가 붙고 등록도 막습니다.
- **색 표시**는 서버가 단어마다 역할을 한 번 정하고 목록·상세·원본 창이 그 결과를 그대로 그립니다: **빨강 = 앞 고정**(A는 원본 앞 4단어, B는 3단어), **파랑 = 원본 핵심(keep)**, **회색 = 그 밖의 원본 단어**, **보라 = AI 다른 이름·용도**, **초록 = AI 맥락**, **주황 = 직접 넣은 단어**(원본에도 AI 키워드에도 없는 말: 직접 고친 이름·셔플의 '넣을 단어'. 셔플로 섞은 원본 단어는 회색·파랑. 넣을 단어·직접 고친 이름도 AI 단어와 같은 기준으로 거름 — 금지어·상표·차단 단어, 무료배송·최저가·정품·국산 같은 판매 조건·품질 주장·원산지 표현은 붙여 써도 뺌), 취소선 = 빠진 원본 단어. 고정 말고는 모든 단어에 색이 붙습니다.
- **금지어 화면 → AI 다른 이름 확인**: 받은 다른 이름(또는 맥락)을 단어별로 모아 많은 순으로 보여 주고, **차단**하면 모든 원본에서 빠지고 아직 안 올린 복사본의 그 단어 든 이름은 새로 만듭니다.
- 요청: 모델 Sonnet 5.5, 요청 1건에 원본 10개(원본 id를 붙여 보내고 id로 맞춤 — 순서에 기대지 않음), `thinking: between_tools`(Haiku는 `disabled`), temperature 안 보냄, max_tokens 3000, **구조화 출력**(`output_config.format`, 설정 `ctx_structured`로 끌 수 있음). 스키마의 개수 제한(maxItems)은 API가 받지 않아 개수는 코드에서 자릅니다.
- 응답에서 **원본마다 따로** 저장합니다. 빠진 원본·형식이 틀린 원본만 재시도 대기, JSON 자체를 못 읽으면 그 요청 전체 재시도.
- 프롬프트 버전(`PROMPT_VER`)을 기록합니다. 프롬프트를 바꾸면 예전 버전으로 받은 원본이 다시 받을 대상이 됩니다.
- 예전 방식(맥락 키워드만)으로 받은 키워드는 이 버전을 처음 켤 때 **초기화**합니다(아직 안 올린 복사본의 맥락 이름도 떼어 '상품명 변경 필요'로, 올라간 상품 이름은 그대로).
- **처리 방식**: 일괄(Message Batches, 50% 할인, 기본) 또는 즉시(요청을 한꺼번에, 최대 50개 동시). 실행 전에 대상 원본 수·요청 수·예상 토큰·예상 비용(원)을 보여 주고 확인을 받습니다(원본당 입력 약 140·출력 약 110토큰 추정 — 실제 시험 뒤 고침, 환율 설정 1,330원). 끝나면 응답 사용량으로 계산한 실제 비용을 **실행 기록 → 맥락 키워드 받기**에 남깁니다.
- 일괄 처리는 배치 id와 요청↔원본 연결을 db에 저장하고 1분마다 확인합니다. **프로그램을 껐다 켜도 이어서 확인**하고, 처리 중인 원본은 다시 보내지 않습니다. 실패·만료·취소된 요청의 원본은 재시도 대기로 둡니다. 왼쪽 아래에 진행 상황과 '지금 확인'·'중지'.
- 이미 키워드를 받은 원본은 다시 부르지 않습니다(요청 0건으로 안내). **원본 상품명이 바뀌면** 그 원본의 키워드와 아직 안 쓴 맥락 이름 후보를 무효로 합니다.
- 키워드를 받으면 이름 후보를 만들고 그 원본의 **이름 없는 복사본에 바로 배정**합니다. 복사 계획을 만들 때도 안 쓴 맥락 후보가 있으면 스토어가 정해진 복사본에 하나씩 배정합니다.
- 예전 재조합·단어 사전·우리말샘·네이버 키워드 기능은 없앴습니다(저장된 데이터는 지우지 않음). **금지어** 메뉴 → **파일에서 가져오기**로 금지어 목록(예: 금지어_721.txt)을 중복 없이 더할 수 있습니다.
- 원본 하나는 **최대 2곳**(설정 `max_copies`, 예전 3).

## 설정이 적용되는 때

설정은 저장한 뒤 **새로 만드는 것부터** 적용됩니다(설정 화면 각 칸에 '적용'으로 표시). 이미 만든 것에는:
- 가격: 설정 화면 맨 위 **'대기 중인 복사본 가격 다시 계산'**(아직 안 올린 복사본만).
- 상품명: **'안 쓴 이름 후보 지우기'** 뒤 다시 만들기 / 복사본 화면에서 '상품명 바꾸기'.
- 원산지 설정을 바꾸면 저장할 때 전체 원본을 자동으로 다시 검사합니다.

## 원산지

기본은 **엑셀 원산지와 상관없이 일괄 지정**: 중국(수입산 > 아시아 > 중국, 코드 0200037). 수입사 칸은 스토어마다 **`{store}협력사`**(예: 가나스토어협력사), 스토어 화면에서 스토어별로 따로 정할 수도 있습니다. 일괄 지정을 끄면 엑셀 원산지를 원산지 코드 표에서 찾습니다(값 전체로 먼저, 띄어쓰기 무시 → 예: '상세페이지 참조' → 03, 없으면 앞 단어로 → '중국(광동)' → 중국).

## 대표 이미지 워터마크

설정 → 워터마크에서 켭니다: 스토어마다 로고 PNG(스토어 화면에서 올림, 투명 배경 권장) 또는 글자(비우면 스토어 이름). 위치는 네 모서리·위아래 가운데, 크기·불투명도·여백 설정. 직사각형 이미지는 네이버 목록에서 가운데 정사각형으로 잘려 보이므로 **그 정사각형 안쪽**에 넣습니다(또는 흰 여백으로 정사각형을 만든 뒤 넣기). 워터마크 넣은 이미지는 스토어마다 따로 올라가고, 설정이나 로고를 바꾸면 다음 등록부터 새로 올립니다. 로고·글자는 스토어 **템플릿**에서 정하고, 미리보기는 설정 → 워터마크와 템플릿 창에 있습니다.

## 상품명 중복 방지

모든 상품명은 띄어쓰기·기호·대소문자를 빼고 비교해서, **33개 스토어 전체에서** 같은 이름이 두 번 나오지 않습니다(데이터베이스 UNIQUE 제약). AI 맥락 키워드 이름은 같은 원본의 다른 이름과 단어가 85% 이상 겹치면 버립니다. 원본 상품명 자체는 기본으로 쓰지 않습니다(원본 스토어와 같은 이름이 되므로, 설정에서 바꿀 수 있음).

## 속도

- 네이버 호출 한도는 스토어(애플리케이션)마다 따로라서 스토어를 나란히 돌립니다. 기본은 33곳 동시, 스토어당 2건.
- 대표·추가 이미지는 스토어마다 네이버에 올려야 하지만, 한 번 내려받은 이미지는 디스크(`data/imgcache`, 기본 5GB)에 보관해 다시 받지 않습니다.
- 상세 이미지가 이미 네이버 이미지 서버(`pstatic.net`) 주소면 그대로 둡니다(설정에서 바꿀 수 있음). 다른 주소의 상세 이미지는 한 번만 올리고 모든 스토어가 같이 씁니다.
- 실제 등록 기록이 쌓이면 예상 시간을 그 평균으로 계산합니다. **실행 기록** 화면에서 1건당 시간과 1만 건 예상 시간을 볼 수 있습니다.

시험 결과(네이버 접속 없이 흉내 낸 시연 모드, 이 저장소의 개발 환경): 원본 10만 개 불러오기 약 47초(엑셀 읽기는 별도로 초당 약 1,300줄), 재조합 이름 28만 개 약 38초, 등록 28만 건 계획 약 11초, 목록 화면 0.2초 이내. 데이터베이스는 원본 10만 개에 약 670MB.

## 작업 기록

실행 기록 화면 맨 위 **작업 기록**에 프로그램에서 한 일이 모두 남습니다(껐다 켜도 남음): 시작·끝 시각(초까지), 걸린 시간, 묶음, 작업, 스토어, 대상 수, 결과, 상태.
- 오래 걸리는 작업(상품명 바꾸기, AI 키워드, 복사, 네이버 등록, 메일 가져오기 …)과 바로 끝나는 작업(삭제·되살리기, 대기에 넣기, 잠금, 카테고리 맞추기 저장, 단어 차단 …).
- **설정·스토어 템플릿 변경**: 무엇이 무엇에서 무엇으로 바뀌었는지 (API 키·비밀번호는 값 없이 '바뀜'만).
- AI 키워드 일괄 처리는 보낸 때와 결과가 온 때가 따로 남습니다. 프로그램이 꺼져 끝을 못 본 작업은 '끝 확인 못 함'.

## 판매자센터를 스토어 계정으로 열기

스토어 '수정'에서 **판매자센터 크롬 프로필**을 고르면(크롬에 있는 프로필 목록이 나옴), 판매자센터 버튼·'스마트스토어센터에서 수정' 링크가 그 프로필로 크롬을 열어 그 스토어 계정으로 바로 들어갑니다. 프로필마다 그 스토어 계정으로 한 번 로그인해 두세요(아이디·비밀번호 자동 입력은 하지 않음). 크롬을 못 찾으면 설정 → API 키 → 크롬 위치.

## 메일함 (구글)

왼쪽 **메일함**: 네이버가 보낸 메일을 지메일에서 읽어 **경고·제재 / 주문·문의 / 인증번호 / 기타**로 나누고 스토어별로 모읍니다(읽기만 함, 읽음 표시도 안 바꿈).
- 준비: 구글 계정 → 보안 → 2단계 인증 → 앱 비밀번호(16자리), 지메일 설정 → IMAP 사용. 설정 → API 키 → 구글 메일함에 주소·앱 비밀번호.
- 스토어 구분: 스토어 '수정'의 **받는 메일 주소**(예: me+redcoco@gmail.com) → 없으면 메일 안의 스토어 이름·주소 → 메일 안 상품번호의 복사본.
- 메일 안의 10자리 상품번호를 복사본과 맞춰 링크(복사본·판매자센터)를 붙입니다. 경고 메일은 처리하면 '확인함' 체크 — 확인 안 한 경고 수가 왼쪽 메뉴에 빨간 숫자로.
- 인증번호 메일은 번호를 크게 보여 줍니다. 자동 가져오기 간격(분)을 넣으면 켜져 있는 동안 계속 가져옵니다.

## 주의

- 상품정보제공고시는 모든 상품을 '기타 재화'로 등록합니다.
- 같은 상품을 자주 지우고 다시 올리는 것은 네이버 검색 정책에서 어뷰징으로 볼 수 있습니다. 최신화 주기는 정책을 확인하고 정하세요.
- 프로그램 밖(스마트스토어센터)에서 지운 상품은 프로그램이 알지 못합니다. 스토어 화면의 **연결 확인**으로 네이버 상품 수를 다시 받으면 남은 자리 계산은 맞춰집니다.
- 같은 원본을 여러 스토어에 올릴 때 네이버는 상품명뿐 아니라 이미지·상세페이지로도 같은 상품인지 판단할 수 있습니다. 상품명만 바꾼다고 중복 판정을 피한다는 보장은 없습니다.
- 다른 판매자의 사진·상세페이지를 허락 없이 가져와 등록하면 저작권 침해로 상품이 삭제되거나 제재될 수 있습니다.
