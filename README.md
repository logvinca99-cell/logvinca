# 스마트스토어 찜 클릭기

네이버 스마트스토어 목록 페이지(80개씩 보기)에서 상품 카드의 찜(♡)을 한 페이지씩 누르는 프로그램입니다. 상품 상세 페이지에는 들어가지 않습니다.

## 설치

```bash
pip install -r requirements.txt
playwright install chrome   # PC에 크롬이 이미 있으면 생략 가능
```

## 실행

`zzim_start.bat`을 더블클릭하면 조작 창이 뜹니다. 크롬보다 항상 위에 떠 있습니다.

- 스토어 주소 칸에 주소를 넣고(여러 개면 한 줄에 하나) **▶ 시작**을 누릅니다.
- **⏸ 일시정지 / ▶ 계속**: 지금 누르는 상품까지 처리하고 멈춥니다.
- **■ 종료**: 작업을 끝냅니다. 다시 시작하면 남은 것부터 이어서 합니다.
- 진행률, 성공·이미 찜·실패·남은 개수, 지금 누르는 상품, 남은 시간이 표시됩니다.

검은 창 모드도 남아 있습니다.

```bash
python zzim.py --console https://smartstore.naver.com/abcstore
python zzim.py --console --file stores.txt
```

옵션
- `--sort-label "최신 등록순"`: 시작할 때 누를 정렬 버튼 글자. 진행하는 동안 순서가 바뀌지 않아야 누락이 없습니다.
- `--delay 600 6000`: 클릭 간격 자동 조절 범위(ms). 1.2초에서 시작해 거절이 없으면 15번마다 10%씩 빨라지고, 거절되면 바로 1.5배 이상 느려집니다. 최소값을 너무 줄이면 네이버가 거절하거나 계정이 제한될 수 있습니다.

## 동작 방식

1. 시크릿 창이 열리면 직접 로그인합니다. 로그인되면 자동으로 시작합니다.
2. "전체상품(총 N개)"를 읽어 페이지 수를 계산합니다.
3. 페이지마다 끝까지 스크롤한 뒤 카드를 한 번에 스캔합니다. 카드 안의 링크 `/products/<ID>`에서 ID를 읽고, 같은 카드 안의 찜 버튼과 짝을 짓습니다.
4. 카드를 화면 좌표순으로 정렬해 5개씩 행으로 묶고 차례로 클릭합니다. 이미 찜한 상품은 건너뜁니다. 클릭이 반영되지 않으면 4초, 8초, 12초 쉬고 다시 시도합니다.
5. 한 페이지가 끝나면 화면 아래 페이지 번호를 눌러 다음 페이지로 갑니다. 상품 목록이 실제로 바뀌었는지 확인합니다.
6. 결과는 `zzim_<스토어명>.csv`에 기록합니다. 중간에 멈춰도 다시 실행하면 처리한 ID는 건너뛰고 이어서 진행합니다.

## 상태 값 (CSV `status`)

| 값 | 의미 |
|---|---|
| clicked | 클릭 후 찜 상태로 바뀐 것을 확인함 |
| already | 실행 전에 이미 찜한 상태였음 |
| clicked? | 클릭은 했지만 상태를 판별하지 못함 |
| fail / error | 실패. 다시 실행하면 재시도함 |

## 처음 실행할 때 확인할 것

- 찜 버튼은 버튼 안에 "찜" 글자(숨김 텍스트 포함)가 있는지로 찾습니다. 찜 상태는 `aria-pressed` 속성이나 "찜하기 취소" 문구로 판별합니다. `clicked?`가 많이 나오면 F12로 버튼 구조를 확인해 `zzim.py`의 `STATE_JS`를 수정하세요.
- `--sort` 값(`st=` 파라미터)은 실제 목록 URL에서 확인하세요.
- 본인 계정 하나로 관심상품을 저장하는 용도로만 사용하세요. 여러 계정으로 찜 수를 부풀리면 네이버 약관 위반입니다.

# 스마트스토어 상품 등록기 (다중 스토어)

수집한 원본 상품(엑셀)을 **인벤토리**에 쌓아 두고, 원본마다 **겹치지 않는 상품명**과 **스토어별 가격**을 붙여 여러 스마트스토어(원본당 최대 3곳)에 **네이버 커머스API**로 등록합니다. 올린 상품은 회차별로 기록해 **최신화(지우고 다시 올리기)**와 **내리기**를 관리합니다. 조작 화면은 브라우저로 열리며 이 PC(127.0.0.1)에서만 접속됩니다.

`upload_start.bat`을 더블클릭하면 실행됩니다. 필요한 프로그램은 처음에 자동으로 설치됩니다.

## 흐름

```
원본 엑셀 ──▶ 원본 상품(인벤토리) ──▶ 눈검수 ──▶ 상품명 후보 ──▶ 등록 계획 ──▶ 등록 ──▶ 판매 중 ──▶ 최신화 / 내리기
  수십만 개      대표 썸네일로 구분      통과만      재조합 / AI /     원본당 최대 3곳    33곳 동시            회차 +1     빈 칸이 생김
                 다시 불러오면 갱신      등록됨      외부 파일 가져오기  이름·가격 배정
```

1. **스토어**: 스토어마다 커머스API 애플리케이션 ID/시크릿을 넣습니다. **여러 개 한 번에 추가**에 엑셀 다섯 칸(이름, ID, 시크릿, 주소, A/S 전화)을 붙여 넣으면 33개를 한 번에 넣을 수 있습니다. **연결 확인**을 누르면 네이버에 이미 있는 상품 수를 받아 와서 남은 자리(기본 한도 1만 개)를 계산합니다.
2. **원본 상품**: 엑셀을 불러오거나 화면에 끌어다 놓습니다. 원본은 **대표 썸네일 주소**로 구분합니다(판매자코드는 스토어마다 바뀌므로 쓰지 않음). 같은 썸네일은 새로 추가하지 않고 내용만 갱신합니다. 썸네일이 없으면 상세 이미지, 그것도 없으면 상품명으로 구분합니다. 불러오면서 바로 검사해 등록 가능 / 경고 / 오류로 나눕니다.
3. **상품명 후보**: 원본마다 쓸 이름을 미리 만들어 둡니다.
   - 재조합: 원본 상품명의 단어를 고르고 순서를 바꿉니다. 무료·즉시. 단어가 적은 상품은 다 못 채울 수 있습니다.
   - AI: Claude API로 원본을 보고 새로 짓습니다(설정에서 API 키·모델). 화면에서 예상 비용을 보여 줍니다.
   - 가져오기: 외부 AI 도구에서 만든 파일을 **상품명 파일 가져오기**로 넣습니다. 원본을 찾는 열(`썸네일`이 가장 정확, 없으면 원본 엑셀의 `판매자코드`나 `원본상품명`)과 `상품명`이 들어간 열(여러 개 가능)이 있으면 됩니다. 한 칸에 여러 이름을 줄바꿈이나 `|`로 넣어도 됩니다.
4. **등록 계획**: 원본을 고르고(조건에 맞는 전체도 가능) **스토어에 올리기 계획**을 누릅니다.
   - 원본 하나는 **최대 3곳**(설정)까지만 올라갑니다. 내린 스토어는 세지 않습니다.
   - 원본마다 N곳이 되도록 골고루, 또는 빈 칸을 모두 채우기 (남은 자리가 많은 스토어부터).
   - 전에 내렸던 스토어에 다시 계획하면 같은 줄이 다음 회차로 살아납니다(같은 이름·가격).
   - 이름은 원본마다 안 쓴 후보에서 하나씩 씁니다(가져옴 → AI → 재조합 순). 모자라면 재조합으로 자동으로 채웁니다.
   - 가격은 스토어마다 원본가 ±3%(설정) 안에서 정하고 100원 단위로 맞춥니다. 같은 상품·같은 스토어는 언제 계획해도 같은 가격입니다.
   - 같은 원본은 한 스토어에 한 번만 올라가고, 스토어 한도를 넘는 건은 만들지 않습니다.
5. **등록**: 스토어·계획으로 거르고 **시작**. 여러 스토어를 나란히 돌리고, 스토어별 진행, 남은 시간, 실패 원인을 보여 줍니다. 일시정지·중단하면 남은 건은 대기로 돌아가고, 실패 건은 다시 시작하면 재시도합니다. **대기·실패 건 계획 취소**를 하면 쓰던 이름이 다시 후보로 돌아갑니다.

## 눈검수 (통과한 원본만 등록)

판매 불가 상품(구매대행 판매 불가 위험 상품, 타정총·네일건, 전기충격기, 어획 어구, 디자인권·브랜드 로고·캐릭터 등)을 눈으로 거릅니다. 오탐(멀쩡한 걸 제외)은 괜찮고 **미탐(문제 상품 등록)은 없게**, 노동은 최소로.

- 원본마다 **검수 대기 / 통과 / 제외**. 새로 불러온 원본은 대기이고, 다시 불러왔는데 상품명·카테고리·썸네일이 바뀌었으면 다시 대기가 됩니다.
- **등록 차단(이중)**: 등록 계획을 만들 때 통과가 아닌 원본은 빼고("검수 안 됨 N / 제외 N"), 실제 등록 직전에 한 번 더 확인합니다(검수 기능 전에 만든 계획, 계획 뒤에 제외된 것, 최신화도 — 최신화는 지우기 전에 막음).
- **눈검수 화면**: 대기 원본을 카테고리 순(대>중>소>세)으로 그리드에 깝니다. 카드 = 대표 썸네일 + 카테고리 마지막 이름 + 상품명 앞 4글자. 건너뛰는 원본은 없습니다.
  - **클릭**: 제외 표시/취소 · **Space**: 표시 안 한 카드를 모두 통과로 저장하고 다음 · **Z**: 방금 넘긴 페이지로 돌아가 고치기 · 마우스를 올리면 크게 + 상품명 전체.
  - 위험 카테고리(설정, 기본 낚시·공구·호신·완구·의류·잡화)는 한 화면 12장(카드 크게), 나머지 24장. 페이지 위에 그 카테고리에서 볼 것(주의 문구, 설정에서 편집)을 띄웁니다.
  - 썸네일을 못 불러오면 '이미지 없음'과 상품명 전체를 보여 주고, 이 카드는 Space로 넘어가지 않아 직접 통과/제외를 눌러야 합니다.
  - 판정은 넘길 때마다 바로 저장됩니다. 창을 닫았다 열어도 이어서 합니다.
- **함정 카드**: 이미 제외한 원본을 약 50장에 1장꼴(설정)로 똑같은 모양으로 섞습니다. 놓치면 "놓친 상품이 있습니다"를 띄우고 그 페이지를 저장하지 않고 다시 보게 합니다. 함정의 원래 판정(제외)은 바뀌지 않습니다. 제외한 원본이 아직 없으면 "함정 카드 없음".
- **결과**: 대기가 0이 되면 이번 회차 본 개수·통과·제외·함정 적중·걸린 시간. '제외한 상품 다시 보기'에서 실수로 제외한 것을 통과로 되살립니다(통과→제외는 원본 상품 화면 상세에서).
- **제외됐는데 판매 중인 복사본**은 따로 목록으로 보여 주고 '제외된 판매 중 상품 내리기'로 내리기를 예약합니다(판매 이력으로 잠긴 것은 빼고 알려 줌).
- 한눈에 보기에 대기·통과·제외·최근 함정 적중률·제외된 판매 중 수, 원본 상품 화면에 검수 필터와 표시, 복사본 CSV에 검수 열.
- 이미지 AI 검사는 나중에 붙입니다(원본에 `ai_flag`/`ai_reason` 자리만 있음).

## 도둑방지

내 상품을 그대로 베껴 몇천 원 싸게 올리는 판매자 대응.

1. **처음 올릴 때 가격을 높여 둠**(기본 +30,000원, 설정 → 도둑방지에서 켬). 최신화 때도 할지는 설정.
2. **베낀 상품 찾기**: 정한 시간(기본 12시간)마다 내 상품명 그대로 네이버 쇼핑을 검색해, 내 스토어가 아닌 곳에서 상품명이 80% 이상 같고 내 높인 가격보다 싼 상품을 찾습니다(네이버 검색 API 키 필요). 찾으면 **바로 원래 가격으로** 되돌립니다 → 그쪽보다 싸짐.
3. 못 찾아도 **정한 날(기본 7일)이 지나면** 원래 가격으로 되돌립니다. 프로그램이 켜져 있을 때 10분마다 확인합니다.
4. **도둑방지 화면**: 올린 뒤 며칠 만에 베꼈는지 분포(되돌리는 날을 정하는 근거), 베낀 것으로 보이는 상품 목록(그쪽 스토어·상품명·가격·링크), 높인 가격으로 올라가 있는 것. 복사본 화면의 '도둑방지 가격' 칸에서 골라 바로 되돌리거나 찾아볼 수 있습니다.
5. 내 스토어 구분은 스토어 이름과 스토어 화면의 '쇼핑 노출 이름'으로 합니다.
6. 가격 되돌리기는 원상품을 읽어 판매가만 바꿔 다시 보내는 방식입니다(커머스API `GET/PUT /v2/products/origin-products/{번호}`).

**대표 이미지 워터마크**(설정 → 워터마크에서 켬): 스토어마다 로고 PNG(스토어 화면에서 올림, 투명 배경 권장) 또는 글자(비우면 스토어 이름). 위치는 네 모서리·위아래 가운데, 크기·불투명도·여백 설정. 직사각형 이미지는 네이버 목록에서 가운데 정사각형으로 잘려 보이므로 **그 정사각형 안쪽**에 넣습니다(또는 흰 여백으로 정사각형을 만든 뒤 넣기). 워터마크 넣은 이미지는 스토어마다 따로 올라가고, 설정이나 로고를 바꾸면 다음 등록부터 새로 올립니다. 미리보기는 도둑방지 화면과 스토어 수정 창에 있습니다.

## 원본과 복사본

불러온 엑셀 한 줄이 **원본**이고, 다른 스토어로 올리는 것은 원본에서 만든 **복사본**입니다(원본당 최대 3곳).
**원본 상품** 화면에서 원본 바로 아래 줄에 복사본이 보입니다: 스토어 코드·이름, 복사한 상품명, 가격(원본 대비 %), 관리코드·회차, 올린 날, 판매 수, 상태. 줄을 누르면 상세(같은 원본의 다른 복사본, 지난 회차, 판매 이력)가 열립니다. 복사본 전체는 **복사본** 화면에서 스토어·상태·올린 날로 거릅니다.


- **판매자 관리코드**를 프로그램이 스토어마다 만들어 등록합니다: `스토어코드-원본번호-회차` (예: `S07-0012345-2` = 스토어 S07, 원본 #12345, 2번째 등록). 스마트스토어센터에서 이 코드로 검색하면 어느 원본의 몇 번째 등록인지 바로 압니다. 형식은 설정에서 바꿀 수 있습니다.
- **원본 상품** 화면의 '스토어 칸'에 원본마다 3칸이 있고, 들어간 스토어 코드가 상태 색으로 표시됩니다(판매 중 초록, 대기 회색, 실패 빨강, 최신화 대기 파랑, 내리기 대기 주황). 빈 칸은 점선입니다. 위의 칸으로 '아직 0곳 / 1~2곳 / 3곳 다 참'을 거릅니다.
- **등록** 화면의 각 줄에는 같은 원본이 몇 곳에 있는지 표시되고, 줄을 누르면 같은 원본의 다른 스토어 등록과 지난 회차가 보입니다.

## 최신화와 내리기 (잠긴 상품은 지우지 않음)

- **잠금**이 걸린 복사본은 최신화·내리기에서 항상 빠집니다. 예약할 때 한 번 거르고, 실행 직전에 그 스토어의 주문을 다시 가져와 한 번 더 확인합니다. 주문을 가져오지 못하면 그 스토어에서는 아무것도 지우지 않습니다.
- 잠금은 두 가지입니다.
  - **자동 잠금 (판매 이력)**: 취소·반품을 뺀 실제 판매(결제 완료·배송·구매확정·교환)가 1건이라도 있으면 잠깁니다. 취소·반품만 있는 복사본은 잠그지 않아 지울 수 있습니다. 아직 '결제 완료'인 주문도 판매로 보고 잠그며, 나중에 취소가 확정되면 다음 주문 가져오기 때 풀립니다.
    설정에서 끌 수 있고, "취소·반품만 있어도 잠금"을 켜면 이력이 조금이라도 있으면 모두 잠급니다.
  - **직접 잠금**: 판매 이력과 상관없이 복사본 화면에서 골라 **잠금** / **잠금 풀기**, 또는 상세에서 **직접 잠금**. '잠금 풀기'는 직접 건 잠금만 풉니다(판매 이력 잠금은 그대로).
- 복사본 화면의 **잠금** 칸으로 잠긴 것만 볼 수 있고, 줄마다 잠금 이유(판매 이력 n개 / 직접 잠금)가 보입니다.
- 판매 이력은 두 곳에서 받습니다.
  - **판매자센터 주문 (판매 현황 화면)**: 스토어마다 커머스API로 판매자센터의 주문을 가져옵니다. 결제뿐 아니라 배송·취소·반품·구매확정 등 상태가 바뀐 주문을 모두 받아 상태를 최신으로 유지합니다. 처음엔 최근 30일, 다음부터는 마지막으로 가져온 때부터 이어서(10분 겹쳐서) 받습니다.
    - **자동 가져오기**: 프로그램이 켜져 있는 동안 60분마다(설정에서 바꿈, 0이면 끔).
    - **기간 지정해서 가져오기**: 시작일~종료일을 골라 지난 주문을 다시 받습니다(네이버가 하루 단위로만 조회해 주므로 날짜 수만큼 나눠 조회).
    - **판매 현황** 화면에서 기간·스토어·맞춤 여부로 거르고, 주문 수·수량·판매된 복사본/원본·취소·반품·못 맞춘 주문과 스토어별 합계를 봅니다. 주문을 누르면 그 복사본 상세가 열립니다.
    - 취소·반품된 주문도 판매 이력으로 셉니다(지우지 않는 쪽이 안전하므로).
  - **판매 이력 파일 가져오기**: 아바닛 같은 주문 수집 웹에서 내려받은 주문 엑셀/CSV. `판매자관리코드`(이 프로그램이 붙인 코드), `상품번호`, `원상품번호`, `상품명` 중 있는 열로 복사본을 찾고, `주문번호`·`수량`·`판매처`·`결제일` 열이 있으면 함께 씁니다. 화면 어디에나 끌어다 놓고 '판매 이력으로'를 골라도 됩니다.
- 주문은 지금 회차와 지난 회차의 상품번호 모두로 맞춥니다.

- **최신화**: 판매 중인 건을 네이버에서 지우고 같은 내용(같은 이름·가격, 설정으로 새 이름)으로 다시 올립니다. 회차가 1 오르고 판매자 관리코드 끝 숫자가 바뀝니다. 지운 회차는 '지난 회차'에 남습니다.
- **내리기**: 네이버에서 지웁니다. 원본의 칸이 비어 다른 스토어(또는 같은 스토어)에 다시 계획할 수 있고, 스토어 자리도 돌아옵니다.
- **스토어별 최신화**: 스토어 화면에서 스토어마다 **최신화**를 누르면 "올린 지 7·30·60·90일 넘은 것 / 판매 중 전체" 중 고른 대상(잠금 제외)이 몇 건인지 보여 주고, 예약하고 바로 그 스토어만 시작합니다.
- 쓰는 법(여러 스토어를 한꺼번에): 복사본 화면에서 **올린 날**(7·30·60·90일 넘음)과 **판매 중**으로 거르고, 고르거나 '조건에 맞는 전체 고르기' → **최신화 예약** / **내리기 예약** → **시작**. 예약은 **대기·실패 취소**로 되돌릴 수 있습니다.
- 스토어 화면과 한눈에 보기에서 스토어마다 판매 중·대기·실패·내림 수와 가장 오래된 등록이 며칠 전인지 보입니다.
- 결과 CSV에 관리코드, 회차, 올린 날, 원본 번호가 들어갑니다.

## 재조합 (토큰 없이 새 상품명 만들기)

1. 원본의 **앞 3단어는 그대로 맨 앞에 고정**합니다(설정에서 개수 변경). **핵심 키워드**가 4번째 이후에 있으면 그것도 빼지 않습니다.
2. 나머지 단어 중 0~3개를 빼고 순서를 섞습니다.
3. **새 단어 1~2개**를 우선순위대로 고릅니다: ① 핵심 키워드의 유의어 → ② **네이버에서 다른 판매자들이 쓴 단어**(아래) → ③ 앞 3단어의 유의어 → ④ 나머지 단어의 유의어 → (설정 시) 엑셀 태그. 카테고리는 따로 정하므로 상품명 만들기에 쓰지 않습니다(설정 `카테고리 이름의 단어를 새 단어로 씀`, 기본 꺼짐). 40% 확률로 덧붙이지 않고 원래 단어 자리에 **바꿔 넣습니다**(예: 접착제 → 본드). 새 단어는 **한글 일반명사만**, **금지 단어**가 들어간 말과 **키프리스에서 상표로 확인된 단어**는 넣지 않습니다.
4. 남는 칸을 **50자까지 채웁니다**(뺐던 원본 단어 → 그래도 남으면 우선순위 높은 새 단어).
5. 버리는 이름: **같은 단어가 3번 이상**(‘테이프/방수테이프/접착테이프’처럼 다른 단어 안에 든 것도 셈), 다른 스토어 이름과 같음, 같은 원본 다른 이름과 (고정한 앞부분 뒤가) 너무 비슷함.

AI 이름과 가져온 이름도 같은 단어 반복·금지 단어·상표 단어로 검사해 걸리면 버립니다(몇 개 버렸는지 알려 줌).
보내 준 엑셀 43개 기준: 앞 3단어 고정 100%, 평균 46자, 새 단어 평균 1.8개, 반복 위반 0. 1만 개 × 3개를 만드는 데 약 10초.

**단어 사전** 화면
- 재조합 미리보기: 상품명이나 원본 번호(#12)를 넣으면 이름을 만들어 보여 줍니다(새 단어 강조, 글자 수).
- 유의어 묶음: 한 줄에 한 묶음(쉼표로 구분). 기본으로 쇼핑 상품명에 흔한 일반명사 묶음이 들어 있고 자유롭게 고칩니다.
- 금지 단어: 새로 넣지 않을 말. 기본으로 상표에서 온 말, 브랜드, 사칭 표현, 근거 없이 쓰면 안 되는 효능·인증·원산지·과장 표현(치료·무독성·항균·KC인증·국산·최초 등)이 들어 있습니다. 원본 상품명에 이 단어가 있으면 원본 상품 화면에 경고로 보입니다.
- **국어사전 (사전 파일 넣기)**: 우리말샘(opendict.korean.go.kr) 또는 표준국어대사전(stdict.korean.go.kr)에 로그인 → **사전 내려받기**에서 받은 파일(zip 그대로, 또는 xml/json)을 '사전 파일 넣기'로 한 번 넣습니다. API 키·외부 주소가 필요 없습니다.
  명사 표제어는 일반명사 판정(키프리스 확인에서 빼기)에, 명사의 비슷한말은 재조합 유의어에 씁니다. 비슷한말은 원본 상품명·네이버 키워드에 실제로 나오는 말끼리만 써서 옛말·전문어가 들어가지 않습니다. 동사·형용사·구·관용구는 넣지 않습니다.
- 우리말샘 API로 유의어 받기(선택): API 키는 신청할 때 서비스 주소(외부 URL)가 필요합니다. 키가 있으면 설정에 넣어, 원본 상품명에 자주 나오는 단어의 '비슷한말'을 받아 묶음으로 저장합니다. 한 번 찾아본 단어는 다시 묻지 않습니다.
  키 받기: opendict.korean.go.kr 회원가입 → 오픈 API → 키 신청(바로 발급) → 설정 → 우리말샘 키에 붙여 넣기 → 단어 사전 → '우리말샘에서 유의어 받기'. 받은 묶음은 '우리말샘에서 받은 묶음' 칸에서 보고 이상한 건 지운 뒤 저장합니다.
- 속성 단어: 재질·모양·색·크기처럼 같은 상품을 서로 다른 상품으로 가르는 말(우드·철제·접이식·화이트·대형 등). 네이버에서 모은 단어에 이 말이 들어 있으면 원본 상품명·옵션·상세설명에 그 말이 있을 때만 씁니다. 끝이 '~식·~형·~색'인 3글자 이상 단어도 속성으로 봅니다.
- 상표 확인(키프리스): **사전에 있는 일반명사는 확인하지 않습니다**(의자·행거·수납함은 상표가 있어도 그 상품의 보통 명칭). 위험한 건 '효도의자'·'왕자행거'처럼 **일반명사를 붙여 만든 조어**라서, 원본 상품명·네이버 키워드·AI/가져온 이름에 나오는 3글자 이상 한글 단어 중 유의어 묶음·속성 단어에 없는 것만 봅니다. 국어사전 파일을 넣었으면 표제어(와 '~용·~형·~식'을 붙인 말)는 건너뜁니다. 사전 파일이 없으면 사전 단어도 걸릴 수 있어 먼저 넣는 걸 권장합니다.
  설정에 KIPRIS Plus 키를 넣고(plus.kipris.or.kr 회원가입 → 상표 정보 검색 API 활용 신청) '조어 상표 확인'을 누르면 **상표명이 정확히 같은** 등록·출원 상표가 있는지 찾습니다. 걸린 조어는 새 단어로 넣지 않고, AI·가져온 이름에 있으면(띄어 쓴 '효도 의자'도) 버리고, 원본 상품명에 있으면 경고합니다. 상관없으면 **허용**. 한 번 확인한 단어는 180일 동안 다시 묻지 않습니다.

## 네이버 키워드 (다른 판매자들이 쓴 단어)

**네이버 키워드** 화면, 또는 원본 상품에서 고른 뒤 '네이버 키워드 모으기'.

1. 원본 상품명 **앞 5단어**로 네이버 쇼핑을 검색합니다(네이버 검색 API, 무료 하루 25,000회). 같은 검색어 결과는 저장해 두고 다시 씁니다(60일).
2. **핵심 키워드**: 앞 5단어 중 검색 결과 상품명에 가장 많이 나오는 단어(결과의 네이버 카테고리 이름과 겹치면 가산점). 원본 화면 → 키워드 탭에서 직접 바꿀 수 있고, 직접 정한 것은 다시 모아도 그대로입니다. 아직 안 모은 원본은 앞 3단어 중 속성이 아닌 마지막 단어로 대충 정합니다.
3. 결과 상품명에서 **판매자 3곳 이상**, 결과의 **8% 이상**에 나온 한글 단어만 모읍니다. 브랜드·제조사·몰 이름(이 들어간 단어), '~몰·~샵·~스토어' 꼴, 할인·당일발송 같은 판촉 문구, 숫자·영문은 뺍니다.
4. 재조합 때 원본마다: **원본에 없는 속성 단어는 뺍니다**(철제 책상에 '우드'·'접이식'이 들어가지 않게), 금지·상표 단어와 화면에서 끈 단어도 뺍니다. 많은 판매자가 쓴 순(검색량을 받았으면 검색량도 반영)으로 최대 15개를 넘깁니다.
5. 네이버 키워드 화면에서 핵심 키워드별로 모은 단어를 보고, 단어를 누르면 그 핵심 키워드에서 끕니다(Shift+클릭은 모든 키워드에서).

키 받기
- 검색 API: developers.naver.com → Application → 애플리케이션 등록 → 사용 API '검색' → Client ID·Secret을 설정 → 네이버 키워드에.
- 검색량(선택): searchad.naver.com 가입(광고비 없이 가능) → 도구 → API 사용 관리 → 고객 ID·액세스 라이선스·비밀키.

비용: 검색 API·검색광고 API·사전 파일은 무료(한도 안). 원본 10만 개면 하루 25,000회 한도라 며칠에 나눠 모읍니다('한 번에 검색할 횟수' 설정, 기본 1,000).

## 상품명 중복 방지

모든 상품명은 띄어쓰기·기호·대소문자를 빼고 비교해서, **33개 스토어 전체에서** 같은 이름이 두 번 나오지 않습니다(데이터베이스 UNIQUE 제약). 재조합은 같은 원본의 다른 이름과 단어 구성이 85% 이상 같거나 앞 두 단어가 같으면 버립니다. 원본 상품명 자체는 기본으로 쓰지 않습니다(원본 스토어와 같은 이름이 되므로, 설정에서 바꿀 수 있음).

## 속도

- 네이버 호출 한도는 스토어(애플리케이션)마다 따로라서 스토어를 나란히 돌립니다. 기본은 33곳 동시, 스토어당 2건.
- 대표·추가 이미지는 스토어마다 네이버에 올려야 하지만, 한 번 내려받은 이미지는 디스크(`data/imgcache`, 기본 5GB)에 보관해 다시 받지 않습니다.
- 상세 이미지가 이미 네이버 이미지 서버(`pstatic.net`) 주소면 그대로 둡니다(설정에서 바꿀 수 있음). 다른 주소의 상세 이미지는 한 번만 올리고 모든 스토어가 같이 씁니다.
- 실제 등록 기록이 쌓이면 예상 시간을 그 평균으로 계산합니다. **실행 기록** 화면에서 1건당 시간과 1만 건 예상 시간을 볼 수 있습니다.

시험 결과(네이버 접속 없이 흉내 낸 시연 모드, 이 저장소의 개발 환경): 원본 10만 개 불러오기 약 47초(엑셀 읽기는 별도로 초당 약 1,300줄), 재조합 이름 28만 개 약 38초, 등록 28만 건 계획 약 11초, 목록 화면 0.2초 이내. 데이터베이스는 원본 10만 개에 약 670MB.

## 엑셀 열 → 등록 항목

| 엑셀 열 | 등록 항목 |
|---|---|
| 판매자코드 | 원본 구분(같으면 갱신), 판매자 관리코드 |
| 상품명 | 원본 상품명 (등록에는 후보 중 하나를 씀) |
| 판매가 / 할인가 | 판매가(스토어별 조정). 할인가가 있으면 같은 비율로 즉시할인 |
| 재고수, 판매상태 | 재고, 판매중/판매중지 |
| 썸네일 | 첫 장 대표이미지, 나머지 추가이미지(최대 9장) |
| 상세설명 | 상세페이지 HTML |
| 카테고리 | `대>중>소>세` 이름으로 카테고리 번호를 찾음 |
| 옵션상품 | 조합형 옵션 그대로 |
| 브랜드 / 제조사 / 모델명 | 네이버쇼핑 검색정보, 상품정보제공고시 |
| 원산지 | 원산지 코드 + 수입자 |
| 인증 | KC 인증 대상 제외 정보 |
| 배송비 | 0이면 무료배송, 아니면 선결제 유료배송 |

## 주의

- 상품정보제공고시는 모든 상품을 '기타 재화'로 등록합니다.
- 같은 상품을 자주 지우고 다시 올리는 것은 네이버 검색 정책에서 어뷰징으로 볼 수 있습니다. 최신화 주기는 정책을 확인하고 정하세요.
- 프로그램 밖(스마트스토어센터)에서 지운 상품은 프로그램이 알지 못합니다. 스토어 화면의 **연결 확인**으로 네이버 상품 수를 다시 받으면 남은 자리 계산은 맞춰집니다.
- 같은 원본을 여러 스토어에 올릴 때 네이버는 상품명뿐 아니라 이미지·상세페이지로도 같은 상품인지 판단할 수 있습니다. 상품명만 바꾼다고 중복 판정을 피한다는 보장은 없습니다.
- 다른 판매자의 사진·상세페이지를 허락 없이 가져와 등록하면 저작권 침해로 상품이 삭제되거나 제재될 수 있습니다.

```
  convert.py    검사, 등록 요청 만들기, 스토어별 가격 (엑셀 열 이름이 바뀌면 여기)
  namegen.py    상품명 정규화, 재조합, AI(Claude API), 이름 검사
  lexicon.py    단어 사전: 유의어 묶음·금지 단어·속성 단어·상표 단어, 같은 단어 반복 검사, 우리말샘 유의어 받기
  kipris.py     키프리스 상표 확인 (사전에 없는 조어만, 상표명이 같은 등록·출원 상표, trademark_check 표)
  review.py     눈검수: 검수 상태·서명, 검수 페이지(카테고리 순·위험 카테고리 밀도·주의 문구), 함정 카드, 회차 기록
  bait.py       도둑방지: 높인 가격·되돌리기, 베낀 상품 찾기(copycats 표)
  watermark.py  대표 이미지 워터마크 (스토어별 로고/글자, 가운데 정사각형 기준 위치)
  keywords.py   네이버 키워드: 쇼핑 검색으로 핵심 키워드 찾기·다른 판매자 단어 모으기·속성 거르기, 검색광고 검색량
  inventory.py  원본 불러오기, 이름 후보, 등록 계획, 목록 조회
  db.py         SQLite (data/inventory.db): sources, names, stores, listings(+회차·할 일), listing_history, plans, runs, images
                예전 버전 db는 열 때 자동으로 바꿈 (PRAGMA user_version)
  naver.py      커머스API (토큰, 카테고리, 이미지, 상품 등록, 상품 수) + 이미지 디스크 캐시 + 시연용 FakeClient
  orders.py     판매 이력: 네이버 주문 가져오기, 주문 파일 가져오기, 복사본과 맞추기
  engine.py     등록 실행 (스토어 여러 곳 동시, 일시정지/중단, 진행 상황)
  tasks.py      불러오기·이름 만들기·계획을 뒤에서 돌리고 진행률 알림
  web.py        화면 서버 (Flask, /api/*)
  static/       화면 (빌드 없음): index.html, app.css, js/core.js + 화면별 js
```

- `python -m uploader` 실행, `--port 9000`, `--no-browser`
- `python -m uploader --fake-api`: 네이버·AI에 접속하지 않고 흉내 냅니다. 화면을 고치거나 시연할 때 씁니다.
- 기록과 설정은 `data/` 폴더에 있습니다. 이 폴더를 지우면 처음 상태가 됩니다. 정기적으로 `data/inventory.db`를 백업하세요.
